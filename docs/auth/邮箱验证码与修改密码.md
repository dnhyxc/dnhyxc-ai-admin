# 邮箱验证码与修改密码

## 1. 背景与目标

后台账号此前只能由种子脚本创建初始管理员，注册用户拿到的是默认「普通用户」角色，没有自助管理账号的能力。本专题补齐以下能力：

- 引入邮件传输模块，让后台用户可以通过邮箱完成二次校验。
- 新增「修改密码」接口：先通过邮箱获取一次性验证码，再校验旧密码，更新新密码。
- 调整种子与注册逻辑，不再默认创建种子管理员账号，角色由注册时自动分配或种子预置。

## 2. 改动范围

- `apps/backend/src/services/mail/mail.module.ts`（新建）
- `apps/backend/src/enum/config.enum.ts`（`SeedEnum` → `EmailEnum`）
- `apps/backend/src/factorys/app-config.factory.ts`（环境校验）

- `apps/backend/src/services/seed/seed.service.ts`、`seed.module.ts`

- `apps/frontend/src/service/api.ts`、`service/index.ts`
- `apps/frontend/src/router/index.tsx`、`menu.ts`

## 3. 实现思路

1. 邮件模块独立成 `MailModule`，通过 `@nestjs-modules/mailer` 加载 `nodemailer` transport，配置来源于 `EMAIL_TRANSPORT` / `EMAIL_FROM` 两个环境变量（Joi 强制必填）。
2. `AuthService` 注入 `MailerService`，新增 `sendEmail` / `verifyEmail` 工具方法，验证码用 `randomUUID + key` 组装唯一 Redis Key，通过 `CACHE_MANAGER` 写入缓存（Redis 优先、未配置则退化为内存缓存）。
3. 修改密码拆两步：`sendChangePasswordCode` 先校验当前邮箱归属并下发验证码（5 分钟有效）；`changePassword` 再走「旧密码 → 邮箱验证码 → 新密码」流程，成功后立即删除验证码 Key，防止重放。
4. 注册时不再依赖种子管理员，改为「首个注册用户自动成为超级管理员」：`isFirstUser = (count === 0)`，其余注册者走 `普通用户` 角色。
5. 种子脚本 `SeedService` 不再创建默认登录账号，仅保证 `超级管理员` / `普通用户` 两个角色存在并绑定菜单，避免绕过注册流程创建账号。
6. 前端新增 `ProfilePage` 路由 `/profile`，内置「账号信息」与「修改密码」两块卡片，验证码按钮带 60 秒倒计时，提交成功后强制登出以强制重新登录。

```typescript
// 新构造函数额外注入 MailerService 与 ConfigService，用于邮件发送与发件人地址
constructor(
	private readonly userService: UserService,
	private readonly jwt: JwtService,
	@Inject(CACHE_MANAGER) private readonly cache: Cache,   // 仍复用原有缓存（Redis 或内存）
	private readonly logsService: LogsService,
	private readonly mailerService: MailerService,          // 新增：调用 nodemailer 发送邮件
	private readonly configService: ConfigService,          // 新增：读取 EMAIL_FROM
	@InjectRepository(Roles)
	private readonly rolesRepository: Repository<Roles>,
) {}

// 通用邮件验证码发送：生成 6 位随机码、下发邮件、缓存后返回唯一 key
async sendEmail(to: string, options?: EmailOptionsDTO) {
	// 允许调用方自定义缓存前缀 key
	const key = options?.key || 'EMAIL';
	// 默认有效期 60 秒，调用方可覆盖
	const timeout = options?.timeout || 60 * 1000;
	try {
		// 生成 100000–999999 范围内的 6 位随机验证码
		const code = Math.floor(100000 + Math.random() * 900000).toString();
		// 通过 MailerService 下发 HTML 邮件
		await this.mailerService.sendMail({
			to,                                 // 收件邮箱（当前后台用户绑定邮箱）
			// 发件人格式："dnhyxc-ai-admin" <EMAIL_FROM>
			from: `"dnhyxc-ai-admin" <${this.configService.get(EmailEnum.EMAIL_FROM)}>`,
			subject: options?.subject || '验证码', // 主题默认「验证码」
			// HTML 正文：标题、验证码、过期提示
			html: `
				<div>
					<h1>${options?.title || 'dnhyxc-ai-admin 验证码'}</h1>
					<h3>接收验证码</h3>
					<p>验证码：<span style="font-size: 20px;">${code}</span></p>
					<p style="font-size: 14px;">此验证码只在 ${timeout / (60 * 1000)} 分钟内有效，请尽快使用，同时请勿泄露给其他人。</p>
				</div>
			`,
		});
		// 用 前缀 + UUID + 收件邮箱 构造唯一 Redis Key，避免冲突
		const REDIS_KEY = `${key}_${randomUUID()}_${to}`;
		// 写入缓存，TTL 到期自动失效
		await this.cache.set(REDIS_KEY, code, timeout);
		// 返回 key 供后续校验使用（前端带回服务端）
		return { key: REDIS_KEY };
	} catch (error: any) {
		// 邮件发送失败统一转为 400 级错误
		throw new HttpException(
			error?.message || '发送邮件失败',
			HttpStatus.BAD_REQUEST,
		);
	}
}

// 校验验证码：先取缓存值，不存在表示已过期；再比对字符串（Number 兼容数字/字符串）
async verifyEmail(verifyCodeKey: string, verifyCode: number) {
	// 从缓存读取先前 set 的验证码
	const codeInCache = await this.cache.get(verifyCodeKey);
	// 缺失则视为过期
	if (!codeInCache) {
		throw new HttpException(
			'验证码已过期，请重新获取',
			HttpStatus.BAD_REQUEST,
		);
	}
	// 数值与字符串均能正确比对
	if (Number(codeInCache) === Number(verifyCode)) {
		return true;
	}
	// 不一致直接返回错误
	throw new HttpException('验证码错误', HttpStatus.BAD_REQUEST);
}

// 下发修改密码的专用验证码：仅允许发送到当前账号已绑定的邮箱
async sendChangePasswordCode(
	userId: number,
	dto: SendChangePasswordCodeDTO,
) {
	// 根据 JWT 中的 userId 反查用户
	const user = await this.userService.findOne(userId);
	if (!user) {
		throw new HttpException('用户不存在', HttpStatus.BAD_REQUEST);
	}
	// 用户未绑定邮箱时不允许下发
	if (!user.email) {
		throw new HttpException('账号未绑定邮箱', HttpStatus.BAD_REQUEST);
	}
	// 前端提交邮箱必须与后台记录一致，防止越权
	if (user.email.toLowerCase() !== dto.email.toLowerCase()) {
		throw new HttpException(
			'当前用户未绑定该邮箱',
			HttpStatus.BAD_REQUEST,
		);
	}
	// 调用通用 sendEmail，指定验证码缓存前缀为 CHANGE_PASSWORD、5 分钟有效
	return this.sendEmail(dto.email, {
		subject: '修改密码验证码',
		title: '修改登录密码',
		key: 'CHANGE_PASSWORD',
		timeout: 5 * 60 * 1000,
	});
}

// 修改密码主流程：前置校验 → 验证码 → 旧密码 → 新密码 → 清理 + 日志
async changePassword(userId: number, dto: ChangePasswordDTO) {
	// 从 DTO 中解构所需字段
	const { email, verifyCode, verifyCodeKey, oldPassword, newPassword } = dto;
	// 新旧密码相同直接拒绝
	if (oldPassword === newPassword) {
		throw new HttpException(
			'新密码不能与原密码相同',
			HttpStatus.BAD_REQUEST,
		);
	}

	// 再次确认用户存在
	const user = await this.userService.findOne(userId);
	if (!user) {
		throw new HttpException('用户不存在', HttpStatus.BAD_REQUEST);
	}
	// 校验邮箱匹配
	if (!user.email || user.email.toLowerCase() !== email.toLowerCase()) {
		throw new HttpException('邮箱不匹配', HttpStatus.BAD_REQUEST);
	}

	// 先校验邮箱验证码（内部已处理过期与错误）
	await this.verifyEmail(verifyCodeKey, verifyCode);

	// 再比对旧密码（bcrypt 校验）
	const isPasswordValid = await comparePassword(oldPassword, user.password);
	if (!isPasswordValid) {
		throw new HttpException('原密码错误', HttpStatus.BAD_REQUEST);
	}

	// 写入新密码（userService.update 内部会 hashPassword）
	await this.userService.update(userId, { password: newPassword });
	// 立即删除验证码，防止重放
	await this.cache.del(verifyCodeKey);

	// 记录一次后台操作日志，便于审计
	await this.logsService.create({
		path: '/api/auth/changePassword',
		method: 'POST',
		data: JSON.stringify({ userId }),
		result: 200,
		action: 'changePassword',
		user,
	});

	return { ok: true };
}
```

**变更摘要**：新增邮件验证码工具链与「发送验证码 / 修改密码」业务方法，所有关键路径都做了用户归属、验证码、旧密码三重校验。

```typescript
// 发送修改密码验证码：需要登录态（JwtGuard）
@Post('/sendChangePasswordCode')
@UseGuards(JwtGuard)
sendChangePasswordCode(
	// 从 JWT 中拿到 userId
	@Req() req: Request & { user?: { userId?: number } },
	// 由 class-validator 校验邮箱格式
	@Body() dto: SendChangePasswordCodeDTO,
) {
	const userId = req.user?.userId;
	// 理论上 JwtGuard 已保证 userId，但仍做防御性判断
	if (!userId) return null;
	// 委托给 AuthService
	return this.authService.sendChangePasswordCode(userId, dto);
}

// 提交新密码：需要登录态
@Post('/changePassword')
@UseGuards(JwtGuard)
changePassword(
	@Req() req: Request & { user?: { userId?: number } },
	@Body() dto: ChangePasswordDTO,
) {
	const userId = req.user?.userId;
	if (!userId) {
		return null;
	}
	return this.authService.changePassword(userId, dto);
}
```

```typescript
async register(dto: RegisterUserDTO) {
	const { username, password, email, captchaId, captchaText } = dto;
	// 保持原有验证码校验逻辑
	const isCaptchaValid = await this.verifyCaptcha(captchaId, captchaText);
	if (!isCaptchaValid) {
		throw new HttpException('验证码错误', HttpStatus.BAD_REQUEST);
	}

	// 用户名唯一性检查
	if (await this.userService.findByUsername(username)) {
		throw new HttpException('用户名已存在', HttpStatus.BAD_REQUEST);
	}
	// 邮箱唯一性检查
	if (await this.userService.findByEmail(email)) {
		throw new HttpException('邮箱已被注册', HttpStatus.BAD_REQUEST);
	}

	// 首个注册用户自动成为超级管理员，后续注册为普通用户
	const isFirstUser = (await this.userService.count()) === 0;
	const role = isFirstUser
		? await this.ensureAdminRole()      // 首个：确保超级管理员角色存在并取之
		: await this.ensureUserRole();       // 后续：普通用户角色
	const user = await this.userService.create({
		username,
		password,
		email,
		roleIds: [role.id],
	});

	// 注册成功写日志
	await this.logsService.create({
		path: '/api/auth/register',
		method: 'POST',
		data: JSON.stringify({ username, email }),
		result: 200,
		action: 'register',
		user,
	});

	// 剥离密码字段返回
	const { password: _, ...userInfo } = user;
	return userInfo;
}
```

**变更摘要**：用 `count() === 0` 判定是否首用户，首个账号自动升级为超级管理员，避免依赖种子脚本。

```typescript
			}),
		);
		this.logger.log('已种子普通用户角色');
		return;
	}

	// 已存在：对比菜单是否与预期一致，不一致则同步
	const want = new Set(userMenus.map((m) => m.id));
	const have = new Set((userRole.menus || []).map((m) => m.id));
	const same = want.size === have.size && [...want].every((id) => have.has(id));
	if (!same) {
		userRole.menus = userMenus;
		userRole.description = '仅可查看关联前台账号的书籍列表';
		await this.rolesRepo.save(userRole);
		this.logger.log('已同步普通用户角色菜单');
	}
}
```

**变更摘要**：拆分 `ensureAdminRoleAndUser` 为 `ensureAdminRole` + `ensureUserRole`，彻底移除默认账号创建逻辑，改由注册流程分配。

### 4.7 前端「个人中心 · 修改密码」页面（新增）

**改动后** · `apps/frontend/src/views/profile/ProfilePage.tsx`（当前，核心片段，约 L15-L91）

```typescript
// ProfilePage 使用 observer 包裹，以便响应 authStore.userInfo 变化
export const ProfilePage = observer(function ProfilePage() {
	// 从全局 store 取 authStore
	const { authStore } = useStore();
	const navigate = useNavigate();
	// 提交改密 / 发送验证码 的 loading 与 60 秒倒计时
	const [submitting, setSubmitting] = useState(false);
	const [sendingCode, setSendingCode] = useState(false);
	const [countdown, setCountdown] = useState(0);
	// 关键：缓存服务端返回的 verifyCodeKey，后续提交改密时带回
	const [verifyCodeKey, setVerifyCodeKey] = useState('');
	// 表单字段类型
	const [form] = Form.useForm<{
		email: string;
		verifyCode: string;
		oldPassword: string;
		newPassword: string;
		confirmPassword: string;
	}>();

	// 读当前登录用户信息
	const user = authStore.userInfo;
	// 拼接角色展示字符串
	const roles =
		user?.roles?.map((r) => r.name).filter(Boolean).join('、') || '—';

	// 首次挂载：若已有邮箱则预填
	useEffect(() => {
		if (user?.email) {
			form.setFieldsValue({ email: user.email });
		}
	}, [user?.email, form]);

	// 倒计时 tick
	useEffect(() => {
		if (countdown <= 0) return;
		const timer = window.setTimeout(() => setCountdown((c) => c - 1), 1000);
		return () => window.clearTimeout(timer);
	}, [countdown]);

	// 点击「获取验证码」
	const sendEmailCode = async () => {
		// 先校验邮箱字段
		const email = await form.validateFields(['email']).then((v) => v.email);
		setSendingCode(true);
		try {
			// 调后端 sendChangePasswordCode
			const res = await sendChangePasswordCodeApi({ email });
			const key = (res.data as { key: string })?.key;
			if (!key) {
				message.error('验证码发送失败');
				return;
			}
			// 保存服务端返回的唯一 key
			setVerifyCodeKey(key);
			message.success('验证码已发送，请查收邮箱');
			// 60 秒倒计时，防止重复点击
			setCountdown(60);
		} finally {
			setSendingCode(false);
		}
	};

	// 提交改密
	const onFinish = async (values: {
		email: string;
		verifyCode: string;
		oldPassword: string;
		newPassword: string;
	}) => {
		// 未获取验证码直接拒绝
		if (!verifyCodeKey) {
			message.error('请先获取邮箱验证码');
			return;
		}
		setSubmitting(true);
		try {
			// 调后端 changePassword
			await changePasswordApi({
				email: values.email,
				verifyCode: Number(values.verifyCode),
				verifyCodeKey,
				oldPassword: values.oldPassword,
				newPassword: values.newPassword,
			});
			message.success('密码已修改，请重新登录');
			// 清空表单与本地缓存 key
			form.resetFields();
			setVerifyCodeKey('');
			// 强制登出，防止旧 token 继续使用
			authStore.logout();
			navigate('/login');
		} finally {
			setSubmitting(false);
		}
	};
	// JSX 结构省略，详见当前源码
});
```

**变更摘要**：前端以 `verifyCodeKey` 贯穿验证码下发与改密两步，成功后强制登出，保证新密码真正生效。

## 5. 兼容性与影响

- 原「种子管理员」默认账号逻辑彻底移除，升级为首个注册用户自动成为超级管理员。**部署升级**时如已有账号不受影响；**全新部署**需业务方自行注册首个账号（或将现有 admin 账号数据库中角色升级为超级管理员）。
- `EMAIL_TRANSPORT` / `EMAIL_FROM` 变为启动必填项，未配置将导致应用无法启动。
- 新增路由 `/profile`，对所有登录用户可见；新增接口 `/auth/sendChangePasswordCode`、`/auth/changePassword` 均需 JWT。

## 6. 风险与回归

- 邮件下发失败：检查 `EMAIL_TRANSPORT`、发件邮箱是否开启 SMTP 授权、网络是否可达。
- 验证码 Key 存 Redis 时若 Redis 不可用会退化为内存缓存（多实例部署下会失效），建议生产固定使用 Redis。
- 改密成功后强制登出需覆盖移动端与 PC 端两侧会话，防止会话泄漏。
