# 项目更新公告（2025–Q1，版本 0.4.0）

面向管理员与普通用户的使用侧变更摘要。开发者细节请跳转到文末「延伸阅读」章节。

## ✨ 个人中心新增「前台账号换绑」

- 场景：旧的前台账号已注销 / 邮箱变更 / 需改绑到另一个前台账号，现在不用联系超管再重置，**个人中心自己就能完成换绑**。
- 入口：右上角头像 → 下拉菜单「个人中心」→ 找到「前台账号绑定」卡片。
  - 未绑定状态：显示「未绑定前台账号」+ 跳转到绑定页的按钮（沿用旧流程）。
  - 已绑定状态：显示当前绑定的前台 `username` + 一个 **换绑** 按钮。
- 换绑二次确认（防误操作）：
  1. 点击「换绑」弹出确认弹窗，提示「换绑后将不再能访问当前前台账号下的书籍与笔记，且该操作不可撤销」。
  2. 点击「确认换绑」后弹出**换绑表单**：需输入 3 项信息 —— 新的前台 username、前台账号登录密码、邮箱（三项都要通过校验）。
  3. 后台在换绑前会**校验密码哈希**、校验邮箱是否匹配该前台账号；通过后才能换绑成功。
- 影响面：
  - 换绑成功后，当前后台账号 `user.aiUserId` 立刻切换为新账号；再次访问前台电子书、笔记、知识库等模块时展示的都是新账号下的数据。
  - 旧的前台账号 **不会被删除**；若未来需要，仍然可以再次换绑回来。

## 👀 超管视角：用户管理列表新增「前台用户名」列

- 场景：在「后台用户管理」页面（仅超管可见），之前只能看到一列 `关联用户` 显示 `aiUserId`（数字，可读性差）。
- 变更：该列现在**直接显示前台用户名**（username），格式：
  - 已绑定：`{username}`；
  - 未绑定：灰色文案「未绑定」。
- 影响面：
  - 超管可**一眼识别**这个后台账号对应哪个前台业务账号，不用再去「前台用户管理」手工对照 id。
  - 分页搜索/筛选：新增/编辑后台用户的表单没有变化；该列为只读展示列。

## 🛡️ 角色管理页新增「分配菜单」编辑能力

- 场景：之前创建角色时一次性勾选了「允许访问的菜单项」，创建后若想调整菜单权限，只能把角色删掉再重建。
- 变更：在「后台角色管理」表格的「操作」列，每个角色现在有两个按钮：
  - **分配菜单**（新增）：点击弹出「编辑角色 - 分配菜单」弹窗，内部是一个树形的菜单选择器，与创建角色时的 `menuKeys` 规则完全一致（勾选 = 允许访问的菜单 key）。
  - 分配菜单弹窗支持 **展开全部 / 折叠全部 / 搜索过滤菜单名称 / 自定义校验（至少勾选一项，否则提交按钮禁用）**。
  - **编辑**（沿用旧）：仍用于修改角色名称、角色描述、是否启用等**基础字段**。
- 保存流程：
  1. 点击弹窗底部「保存」后，会先关闭弹窗，再调用修改接口 `PATCH /roles/{id}`（只传 `menuKeys`）。
  2. 成功后通过**页面顶部的全局 Alert（绿色成功条）** 5 秒自动消失，同时表格自动刷新，菜单权限立即生效。
- 影响面：
  - 下次该角色下的用户再登录时，侧栏菜单、路由访问都会按新的 `menuKeys` 过滤。
  - 当前已登录的该角色用户：**会在接口请求返回 403 时被全局拦截**，自动重定向到无权限页（见下一节「全局无权限提示」）。

## 🔔 全局无权限提示 + 页面加载遮罩

### 403 拦截：不吞错误了，统一弹窗提示

- 场景：之前某个接口返回 403（例如角色 `menuKeys` 被超管修改后，当前用户还停留在原页面，或者直接通过 URL 跳转访问了无权模块）时，前端只在 Console 打一条 log，页面像卡住了一样，用户根本不知道发生了什么。
- 变更：
  - 在每个带 `{ auth: true }` 的请求拦截器里，**只要状态码是 403**，就不再走页面自己的 error 分支，而是**立即弹窗展示全局错误 Alert**：
    > 「当前账号无访问权限，请联系管理员分配权限。」
  - 错误 Alert 出现在**页面右上角**（红色），5 秒自动消失，或点击右侧「×」手动关闭。
  - 同时把页面 URL 自动导航到 `/forbidden`（无权限页），避免用户停留在一个看不到真实数据的空白列表上。
- 影响面：**所有请求都会被统一处理**（不再需要每个页面单独弹 message.error）。除了 403 以外的错误（如 404、500、业务校验失败 `code !== 0`）仍然走页面自身的 error 分支提示。

### 加载遮罩：所有页面现在都有统一的 Loading 动画

- 场景：之前页面在初次加载数据时，表格是空白的、没有任何「加载中」的提示，用户误以为数据为空。
- 变更：
  - 只要页面在**请求列表数据 / 分页切换 / 搜索过滤 / 刷新数据**，整个页面的内容区（含筛选条、表格）会盖上一层半透明的遮罩，中间出现一个炫酷的三层圆环 Loading 动画 + 「加载中...」文字波浪呼吸效果。
  - 动画颜色自动跟随当前主题的「主色（--color-primary）」，深浅色模式都适配。
  - 操作按钮（删除/保存/分配菜单等）在提交请求期间同样会触发该全局遮罩，防止用户重复点击。
- 影响面：以下 10 个页面的 loading/error 状态都已接入统一的遮罩：
  - 仪表盘、用户管理、角色管理、前台用户管理、前台书籍管理、前台知识库管理、前台回收站、前台笔记管理、前台日志管理、个人中心（菜单编辑弹窗的保存动作亦会触发）。
- 关闭时机：请求成功 / 失败后自动关闭，无需手动操作。

## 🎨 视觉统一：所有表格采用 8px 对称圆角

- 场景：之前 Ant Design 的 Table 顶部有圆角、与筛选卡片/标题拼接观感割裂，旧方案把顶部圆角强制压平；压平后顶部看起来方方正正、底部却圆润，整体视觉不对称。
- 变更：全局表格（wrapper / table / 分页容器）统一采用 `8px` 圆角：
  - 顶部、底部都是 8px，**对称圆润**。
  - 分页条（底部分页区域）顶部角保持 0，与表格底贴合不留白边；分页条底部为 8px，构成闭合视觉。
  - 内部行/单元格的边角则全部 `border-radius: 0`，防止行与行之间出现「小凹角导致的白边」。
- 影响面：
  - 用户管理、角色管理、AI 用户/电子书/知识库/笔记/日志等 8 个列表页的视觉风格统一。
  - 筛选卡片与表格之间保留了 `pb-4` 的间距，两者现在是**两张独立的圆角卡片**，视觉层级清晰。
  - 深色/浅色模式下表现一致。

## 🐞 其他修复与细节优化

- **修改密码**：发送邮箱验证码按钮现在会根据 `loading` 状态禁用且文字切换为「发送中...」，与注册流程行为一致。
- **全局 NoticeStore 单例**：
  - 页面里的 `useState<boolean>` 的 `loading`、`message.error()` 提示全部收敛到一个 MobX Store，避免重复写同一段 open/close 代码。
  - 未来任何页面，只要 `await noticeStore.runWithLoading(fn, '正在提交...')` 一行就能同时获得「提交中 loading 遮罩 + 成功自动提示 + 失败自动提示」三件套。
