# 表格顶部圆角去除（历史方案）

> 主文档：最新视觉方案见 [表格圆角样式调整](./表格圆角样式调整.md)（全表统一 8px 圆角，对称圆润风格）；本文档为历史方案留存参考。

## 1. 背景与目标

在后台管理系统中，列表页面通常由「Tabs 切换栏 / 筛选条件条 / 搜索区」与「数据表格」上下紧密组合而成。Ant Design 的 Table 组件默认四周均带有圆角（顶部、底部各有左上/右上圆角），这导致表格上边缘与筛选条下边缘之间产生视觉断层——筛选条底边是直角或轻微圆角，而 Table 顶边却有明显圆角，二者衔接不自然。

本专题的目标是：

- **全局移除所有 antd Table 组件的顶部圆角**（左上、右上均为 0），使 Table 顶边与上方的筛选条 / Tabs / 搜索区能够无缝贴合，形成一体化的视觉效果。
- **保留 Table 底部的原有圆角**，保证卡片底部的视觉完整性。
- 覆盖 Table 的全部子结构（表头容器、表体容器、固定列容器、首行首/尾单元格等），避免遗漏局部仍残留圆角的场景。
- 兼容 Light / Dark 两种主题、支持左右固定列、兼容 RTL（从右向左）书写模式。

## 2. 改动范围

本次改动仅涉及两处前端基础文件，不改动任何业务页面组件代码：

| 序号 | 文件路径 | 改动类型 | 说明 |
| --- | --- | --- | --- |
| 1 | `apps/frontend/src/theme/tokens.ts` | 新增 Table 组件 token | 在 `buildThemeConfig` 返回值的 `components.Table` 中，将 `borderRadius`、`borderRadiusOuter`、`borderRadiusLG` 三个与圆角相关的组件级 token 全部设置为 `0`，从主题配置层面"软清除"Table 默认圆角。 |
| 2 | `apps/frontend/src/index.css` | 新增全局 CSS 覆盖规则 | 在 `.dark` 样式块结束后、`.login-grid` 开始前插入三段针对 Table 的全局 CSS，使用 `:where()` 选择器降低特异性（避免误伤用户自定义样式），并配合 `!important` 强制覆盖 antd 内联及组件级圆角，形成"硬保险"。 |

两份改动组合生效：AntD token 负责"配置层面默认给 0"，全局 CSS 负责"运行时样式层面强制为 0"，形成双保险，确保任何场景下 Table 顶边圆角都会被彻底去除。

## 3. 实现思路

### 3.1 CSS 与 AntD token 双保险思路

Ant Design v5 通过 `ThemeConfig.components.Table.borderRadius*` 系列 token 控制 Table 圆角，但仅修改 token 在以下场景可能仍有残留：

1. antd 部分子结构（如固定列首行单元格、分页上下包裹器）的圆角样式并不完全遵循 token，而是写死在 CSS 中。
2. 用户自定义样式或第三方二次封装组件可能给 Table 手动加了圆角。
3. 动态切换主题或热更新后，token 的重新计算顺序可能导致短暂闪回圆角。

因此需要"双保险"：
- **Token 层**：`components.Table.borderRadius / borderRadiusOuter / borderRadiusLG = 0`，让 antd 在生成样式时默认不给 Table 加任何圆角。
- **CSS 层**：全局 `:where(.ant-*) { border-top-*-radius: 0 !important }` 强制覆盖 Table 所有相关元素的顶部圆角属性，彻底兜底。

### 3.2 使用 `:where()` 选择器降权重避免误伤

`:where()` 伪类的特异性（CSS Specificity）恒为 0，意味着即使全局写了 `:where(.ant-table-wrapper) { ... !important }`，**用户只要在业务代码中写一条普通的 `.my-custom-table { border-top-left-radius: 8px; }` 不带 `!important` 的规则，依然可以覆盖全局默认值**。这保证了：

- 对没有自定义样式的 99% 列表页，强制去除顶部圆角。
- 对少数需要特殊样式的表格，业务开发者仍然可以**轻松覆盖**，不会陷入"全局样式权太高无法覆盖"的维护困境。
- 相较于直接写 `.ant-table-wrapper { ... }`（特异性 = 10），`:where(.ant-table-wrapper)`（特异性 = 0）对业务样式零侵入。

### 3.3 逻辑属性 `border-start-start` 兼容 RTL

除了常规的物理属性 `border-top-left-radius` / `border-top-right-radius` 之外，规则中还同步设置了逻辑属性 `border-start-start-radius` / `border-start-end-radius`。这是因为：

- 在 LTR（从左到右，默认中文/英文）模式下，`border-start-start-radius = border-top-left-radius`，`border-start-end-radius = border-top-right-radius`。
- 在 RTL（从右到左，如阿拉伯语、希伯来语）模式下，`border-start-start-radius = border-top-right-radius`，`border-start-end-radius = border-top-left-radius`。

同时设置物理属性 + 逻辑属性，可确保无论页面采用哪种书写方向，**块起始方向（顶部）的两个角都强制为 0**，避免 RTL 场景下顶边仍出现圆角。

### 3.4 固定列场景覆盖

AntD Table 在开启左右固定列（`fixed: "left"` / `fixed: "right"`）时，会渲染额外的 `.ant-table-cell-fix-left` / `.ant-table-cell-fix-right` 容器，并通过单独的样式给固定列首行的首尾单元格加圆角。如果不覆盖这些选择器，即使普通表格已经是直角，**带固定列的表格首行固定列处仍会有圆角残留**。

因此专门加入第三段 CSS：

- `.ant-table-cell-fix-left` / `.ant-table-cell-fix-left-last`：左侧固定列及其最后一列。
- `.ant-table-cell-fix-right` / `.ant-table-cell-fix-right-first`：右侧固定列及其第一列。

对这些元素也强制将顶部两个圆角设为 0，保证固定列场景与普通表格视觉一致。

**改动前** · `apps/frontend/src/theme/tokens.ts`（基线，约 L48–L70）

```typescript

        return {
                // 根据主题模式选择 AntD 内置算法：dark 模式使用 darkAlgorithm，否则使用默认亮色算法
                algorithm: isDark ? theme.darkAlgorithm : theme.defaultAlgorithm,
                // 开启 antd v5 CSS Variable 模式，并指定前缀 key，避免与其它主题变量冲突
                cssVar: { key: 'dnhyxc-admin' },
                // 全局 token 块：影响所有组件的默认色、圆角、字体等基础视觉
                token: {
                        // 主色：使用外部传入的 primaryColor（来源于预设色板或用户自定义色）

                },

        };
```

```css
/* 逗号：选择器列表分隔符 */
:where(.ant-table-tbody > tr:first-child > td:last-child) {
    /* 表体第一行最后一个 <td>：部分 antd 版本会给表体首行尾单元格带右上圆角 */
    /* 左上方物理圆角强制为 0：移除表头/表体首行单元格在左上角的默认圆角 */
    border-top-left-radius: 0 !important;
    /* 右上方物理圆角强制为 0：移除表头/表体首行单元格在右上角的默认圆角 */
    border-top-right-radius: 0 !important;
    /* 逻辑属性：块起始方向的起始端圆角强制为 0；LTR = 左上，RTL = 右上，兼容从右向左布局 */
    border-start-start-radius: 0 !important;
    /* 逻辑属性：块起始方向的结束端圆角强制为 0；LTR = 右上，RTL = 左上，兼容从右向左布局 */
    border-start-end-radius: 0 !important;
/* 第二段单元格选择器声明块的右花括号：thead / tbody 首行单元格圆角规则完毕 */
}

/* 第三段：针对左右固定列场景的特殊类名，强制顶部两个圆角为 0 */
/* 选中所有左侧固定列单元格：由 antd 在使用 fixed: "left" 时自动追加 */
:where(.ant-table-cell-fix-left),
/* 逗号：选择器列表分隔符 */
:where(.ant-table-cell-fix-right),
/* 选中所有右侧固定列单元格：由 antd 在使用 fixed: "right" 时自动追加 */
/* 逗号：选择器列表分隔符 */
:where(.ant-table-cell-fix-left-last),
/* 选中左侧固定列组中最后一列的单元格：antd 会额外标记此列作为左侧固定结束边 */
/* 逗号：选择器列表分隔符 */
:where(.ant-table-cell-fix-right-first) {
    /* 选中右侧固定列组中第一列的单元格：antd 会额外标记此列作为右侧固定起始边 */
    /* 左上方物理圆角强制为 0：移除固定列首行左上角默认圆角（通常出现在 fix-left-last） */
    border-top-left-radius: 0 !important;
    /* 右上方物理圆角强制为 0：移除固定列首行右上角默认圆角（通常出现在 fix-right-first） */
    border-top-right-radius: 0 !important;
    /* 逻辑属性：块起始方向的起始端圆角强制为 0；兼容 RTL 下固定列位置对调后的顶部圆角 */
    border-start-start-radius: 0 !important;
    /* 逻辑属性：块起始方向的结束端圆角强制为 0；兼容 RTL 下固定列位置对调后的顶部圆角 */
    border-start-end-radius: 0 !important;
/* 第三段固定列选择器声明块的右花括号：固定列圆角规则完毕 */
}

/* ========== Table 顶部圆角去除全局规则新增结束 ========== */

/* 登录页网格布局类：登录表单与装饰区左右两栏网格的样式起点 */
.login-grid {
    /* 登录网格声明块内部的首行属性占位：此处代表 .login-grid 的样式内容起点 */
```

## 5. 兼容性与影响

| 维度 | 影响评估 | 说明 |
| --- | --- | --- |
| **Light / Dark 主题** | 无负面影响 | Token 层与 CSS 层的修改均不依赖具体颜色值，仅控制圆角；两种主题下行为一致。 |
| **固定列（左右 fixed）** | 正向覆盖 | 第三段 CSS 专门针对 `cell-fix-left/right*` 进行了兜底，固定列首行不会残留圆角。 |
| **可滚动表格（横向/纵向）** | 正向覆盖 | `ant-table-container / ant-table-header / ant-table-body / ping-*` 全部在第一段中被覆盖，滚动容器不残留圆角。 |
| **RTL（从右向左布局）** | 兼容 | 同时设置了物理属性与逻辑属性 `border-start-start/end-radius`，RTL 下块起始端（顶边）两角仍可保证为 0。 |
| **分页 / 总结栏（Summary）** | 保留底部圆角 | 所有规则仅修改 `top` / `start` 方向的圆角，未触碰 `bottom` / `end` 方向，表格底部与分页卡片组合处圆角原样保留。 |
| **业务自定义样式覆盖** | 零侵入 | 使用 `:where()` 将选择器特异性降为 0，业务代码只需普通类名即可重新定义圆角，无需提升优先级。 |
| **AntD 版本升级** | 低风险 | 覆盖的类名（`ant-table-wrapper / ant-table / ant-table-thead / cell-fix-left` 等）均为 antd 官方稳定公开类名，版本间极少变更；token 层 `borderRadius*` 亦是官方文档公开组件级 token。 |
| **性能影响** | 可忽略 | 新增的三条 CSS 规则约 50 行，`:where()` 不产生额外匹配成本，首屏加载与渲染性能无感知变化。 |

## 6. 验收清单

以下清单用于验证"表格顶部圆角去除"功能已正确落地且未引入回归：

- [ ] **基础列表页**：访问任意一个包含 Table 的列表页（如用户列表、日志列表），确认 Table 顶边左上/右上两个角均为直角（90° 无圆弧）。
- [ ] **底部圆角保留**：上述列表页中，确认 Table 底部（与分页衔接处或空态下方）仍保留原有圆角或视觉一致，未被误改为直角。
- [ ] **Tabs + 筛选条 + Table 组合**：访问顶部有 Tabs 切换 / 筛选条件条 / 搜索框，下方紧邻 Table 的页面，确认筛选条底边与 Table 顶边无缝贴合、无视觉断层。
- [ ] **Dark 主题切换**：在系统设置中切换到暗色主题，重复上述三条检查，确认暗色模式下同样为顶边直角、底部圆角保留。
- [ ] **横向滚动场景**：找到列数较多、触发横向滚动条的 Table，检查 Table 顶边（包括 `ping-left / ping-right` 阴影容器的顶边）无圆角。
- [ ] **纵向滚动 + 固定表头**：使用了 `scroll={{ y: XXX }}` 并开启固定表头的 Table，检查 `.ant-table-header` 容器顶边为直角，首行 th/td 首末单元格无圆角。
- [ ] **左侧固定列**：使用了 `fixed: "left"` 的列，检查表头第一行左侧固定列最后一列（`cell-fix-left-last`）的顶边无圆角残留。
- [ ] **右侧固定列**：使用了 `fixed: "right"` 的列，检查表头第一行右侧固定列第一列（`cell-fix-right-first`）的顶边无圆角残留。
- [ ] **左右同时固定列**：同时存在 left + right 固定列的 Table，检查顶边左右两个角均为直角，无任何圆弧。
- [ ] **业务样式可覆盖性（可选）**：在任意页面给某个 Table 加自定义 class，并写一条普通 CSS `.my-table { border-top-left-radius: 12px; }`（不带 `!important`），确认该自定义圆角可生效，验证全局 `:where()` 未造成优先级死锁。
- [ ] **Table 组件 token 验证**：打开浏览器 DevTools 元素面板，定位到 `.ant-table` 或 th/td，确认 antd 注入的 CSS Variable / 内联样式中 Table 相关 borderRadius token 为 0（若有）。
- [ ] **非 Table 组件未受影响**：检查 Button / Input / Card / Modal / Tag 等其它常用组件的圆角，确认仍为默认 8 / 12px，未被全局 Table CSS 误伤。
