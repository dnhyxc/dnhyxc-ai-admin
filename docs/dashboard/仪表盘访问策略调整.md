# 仪表盘访问策略调整

## 1. 背景与目标

仪表盘此前对所有登录用户开放，调用 `/dashboard/overview` 接口返回双库业务指标，其中包含「今日活跃用户、会员分布、模块调用次数」等敏感聚合信息。这些指标对普通用户（仅关心自己书籍的前台账号绑定用户）没有业务价值，且暴露了业务整体数据。本专题实现：

- 后端 `DashboardController` 收紧为仅 `ADMIN` 角色可访问。
- 前端 `DashboardPage` 在渲染前判断当前身份，若为普通用户则立即 `Navigate` 到其首个有权限的菜单，避免渲染空数据或错误请求。
- 路由层新增 `HomeIndex` 分流组件，根路径 `/` 不再直接挂 `DashboardPage`，避免先渲染看板再发 overview 请求的闪动。

## 2. 改动范围

- `apps/backend/src/services/dashboard/dashboard.controller.ts`
- `apps/frontend/src/views/dashboard/DashboardPage.tsx`
- `apps/frontend/src/router/index.tsx`（`HomeIndex`）
- `apps/frontend/src/router/menu.ts`（`resolveHomePath`）

## 3. 实现思路

1. 控制器层收紧：`@Roles(Role.ADMIN, Role.USER)` → `@Roles(Role.ADMIN)`，普通用户直接拿 403。
2. 页面层兜底：`DashboardPage` 内部判断 `authStore.isSuperAdmin`，非超管时立即 `Navigate` 到 `resolveHomePath` 返回的路径，且跳过 `overviewApi` 调用。
3. 路由层优化：新增 `HomeIndex` 组件，根路径 `/` 先经 `HomeIndex` 分流，超管才渲染 `DashboardPage`；否则重定向到首个有权限菜单，避免挂载看板时触发 overview 请求后再卸载的闪动。

### 4.2 `DashboardPage` 页面内兜底跳转

**改动前** · `apps/frontend/src/views/dashboard/DashboardPage.tsx`（基线，约 L115-L135）

```typescript
export function DashboardPage() {
	const [stats, setStats] = useState<DashboardStats>(emptyStats);
	const [loading, setLoading] = useState(true);

	useEffect(() => {
		// 旧版：所有用户都去请求 overview，失败则静默
		overviewApi()
			.then((res) =>
				setStats({ ...emptyStats, ...(res.data as DashboardStats) }),
			)
			.catch(() => {})
			.finally(() => setLoading(false));
	}, []);
	// 渲染完整看板
}
```

**改动后** · `apps/frontend/src/views/dashboard/DashboardPage.tsx`（当前，约 L116-L150）

```typescript
// observer 包裹以响应 authStore 变化
export const DashboardPage = observer(function DashboardPage() {
	const { authStore } = useStore();
	const [stats, setStats] = useState<DashboardStats>(emptyStats);
	const [loading, setLoading] = useState(true);

	// 仅超管才会发请求
	useEffect(() => {
		if (!authStore.isSuperAdmin) {
			setLoading(false);   // 普通用户直接跳过请求
			return;
		}
		overviewApi()
			.then((res) =>
				setStats({ ...emptyStats, ...(res.data as DashboardStats) }),
			)
			.catch(() => {})
			.finally(() => setLoading(false));
	}, [authStore.isSuperAdmin]);    // 依赖身份

	// 非超管：立即跳转到首个有权限菜单
	if (!authStore.isSuperAdmin) {
		return (
			<Navigate
				to={resolveHomePath({
					isSuperAdmin: false,
					roles: authStore.userInfo?.roles,
				})}
				replace
			/>
		);
	}

	// 以下只有超管能到达
	return (/* ... 看板 JSX ... */);
});
```

**变更摘要**：前端兜底 + 后端收紧双重保护，即使绕过前端直接请求接口也会被 403 拦截。

### 4.3 路由层 `HomeIndex` 分流

**改动后** · `apps/frontend/src/router/index.tsx`（当前，`HomeIndex` + 路由配置，约 L32-L65）

```typescript
// 根路径分流：超管看仪表盘，普通用户直接进有权限的首页，避免先挂载看板再请求 overview
function HomeIndex() {
	const { authStore } = store;
	if (authStore.isSuperAdmin) {
		return <DashboardPage />;      // 超管：才渲染看板
	}
	return (
		<Navigate
			to={resolveHomePath({
				isSuperAdmin: false,
				roles: authStore.userInfo?.roles,
			})}
			replace
		/>
	);
}

export const router = createBrowserRouter([
	{ path: '/login', element: <LoginPage /> },
	// ...
	{
		path: '/',
		element: (
			<RequireAuth>
				<RequireAiBound>
					<AdminLayout />
				</RequireAiBound>
			</RequireAuth>
		),
		children: [
			// 旧版：{ index: true, element: <DashboardPage /> }
			// 新版：走 HomeIndex 做分流
			{ index: true, element: <HomeIndex /> },
			{ path: 'profile', element: <ProfilePage /> },
			// ...其他业务子路由
		],
	},
]);
```

**变更摘要**：把首页分流上移到路由层，避免先渲染 `DashboardPage` 再发起 overview 请求的闪动。

## 5. 兼容性与影响

- 已存在的普通用户角色不会再看到仪表盘；若其旧收藏夹仍指向 `/`，会被自动重定向到 `/ai-ebooks`（或其绑定角色首个菜单）。
- 超管体验与此前完全一致。
- 若有第三方接口消费者调用 `/dashboard/overview`，需要升级为超管 token，否则将收到 403。

## 6. 风险与回归

- 回归建议：
  1. 超管登录 → 首页渲染正常、overview 正常请求。
  2. 普通用户登录 → 首页直接跳到 `/ai-ebooks`，不渲染看板。
  3. 普通用户手动访问 `/` → 立即重定向，控制台无报错。
  4. 普通用户构造 `GET /dashboard/overview` → 接口返回 403。
