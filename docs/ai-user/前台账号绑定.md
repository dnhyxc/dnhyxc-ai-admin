# 前台账号绑定

> 延伸阅读：[前台账号换绑](./前台账号换绑.md)（已绑定后的换绑流程、用户列表前台用户名回显）

## 1. 背景与目标

后台的「普通用户」角色没有自己的书籍数据，所有书籍都归属前台 `dnhyxc-ai` 业务库的用户。为了让普通用户登录后能看到自己的书籍列表，需要将后台账号与某个前台账号建立**一对一绑定关系**。本专题实现：

- 后台新增 `User.aiUserId` 字段记录关联的前台账号 id。
- 新增 `/ai-user/bind` 接口：校验前台账号存在性与邮箱匹配，并绑定到当前后台用户。
- 未完成绑定的普通用户登录后强制进入「绑定前台账号」页面，防止越权查看他人数据。
- 管理员可在「后台用户管理」页直观查看每个后台用户绑定的 `aiUserId`。

## 2. 改动范围

- `apps/backend/src/services/user/user.entity.ts`（新增 `aiUserId` 字段）
- `apps/backend/src/services/user/user.service.ts`（`aiUserId` 读写、`findByAiUserId`）
- `apps/backend/src/services/user/dto/update-user.dto.ts`（`aiUserId` 可选字段）

- `apps/frontend/src/views/users/UsersPage.tsx`（展示「前台账号」列）

## 3. 实现思路

1. 在后台 `User` 表增加 `aiUserId` 可空外键（不做数据库外键约束，因为前后台分属两个 MySQL 库）。
2. 绑定接口仅允许当前登录的后台用户自助绑定，不允许管理员代绑；这样避免管理员误操作把多个后台账号绑到同一前台账号。
3. 绑定前做三重校验：前台账号存在、邮箱与前台记录一致、该前台账号未被其他后台账号绑定。
4. 普通用户登录后，`AuthStore.needsAiBind` 为 `true` 时，前端路由守卫 `RequireAiBound` 强制跳转 `/bind-ai-user`；绑定成功后通过 `patchUserInfo` 回写本地 store 与 `localStorage`，下次登录直接生效。
5. 管理员用户管理页新增「前台账号」列，显示带 `Tag` 样式的 `aiUserId` 或「未绑定」，便于排查。

### 4.3 `AiUserService.bindForAdminUser` 绑定主流程

**改动后** · `apps/backend/src/services/ai-user/ai-user.service.ts`（当前，`bindForAdminUser` 方法，约 L51-L85）

```typescript
// 普通用户自助绑定前台账号：用户名 + 邮箱须与前台账号一致
// 绑定后书籍等数据按 aiUserId（前台 user.id）过滤
async bindForAdminUser(adminUserId: number, dto: BindAiUserDTO) {
	// 前置检查 AI 业务库是否可用
	this.assertReady();
	// 根据 JWT userId 反查后台用户
	const adminUser = await this.userService.findOne(adminUserId);
	if (!adminUser) {
		throw new BadRequestException('用户不存在');
	}

	// 1. 前台账号存在性校验（用用户名查 AI 库）
	const aiUser = await this.findByUsername(dto.username.trim());
	if (!aiUser) {
		throw new BadRequestException('前台账号不存在，请检查用户名');
	}
	// 2. 前台用户名 + 邮箱一致性校验（大小写不敏感）
	if (aiUser.email.toLowerCase() !== dto.email.trim().toLowerCase()) {
		throw new BadRequestException('前台用户名与邮箱不匹配');
	}

	// 3. 查重：该前台账号是否已被其他后台用户绑定
	//    exclude 自己，允许用户重新绑定同一个前台账号
	const occupied = await this.userService.findByAiUserId(
		aiUser.id,
		adminUserId,
	);
	if (occupied) {
		throw new BadRequestException('该前台账号已被其他后台用户绑定');
	}

	// 4. 写回后台用户的 aiUserId
	await this.userService.update(adminUserId, { aiUserId: aiUser.id });
	// 重新查询用户，拿到完整 roles/menus 以便前端更新会话
	const updated = await this.userService.findOne(adminUserId);
	if (!updated) {
		throw new BadRequestException('绑定失败');
	}
	// 剥离密码后返回给前端
	const { password: _, ...userInfo } = updated;
	return {
		ok: true,
		aiUsername: aiUser.username,   // 便于前端展示
		...userInfo,                    // 含 aiUserId、roles 等
	};
}
```

**变更摘要**：绑定流程严格按「存在性 → 邮箱一致 → 查重 → 写回」四步走，确保数据正确与安全。

### 4.4 `AiUserController` 暴露绑定接口

**改动后** · `apps/backend/src/services/ai-user/ai-user.controller.ts`（当前，`bind` 方法，约 L52-L63）

```typescript
// 当前登录用户自助绑定前台账号
@Post('/bind')
// ADMIN / USER 均可调用（超管若误触也能绑定）
@Roles(Role.ADMIN, Role.USER)
bind(
	// 从 JWT 中取 userId
	@Req() req: Request & { user?: { userId?: number } },
	// 绑定参数（username + email）
	@Body() dto: BindAiUserDTO,
) {
	const userId = req.user?.userId;
	if (!userId) return null;    // 理论上不会触发，防御性判断
	return this.aiUserService.bindForAdminUser(userId, dto);
}
```

```typescript
	aiUserId?: number | null;             // 新增：绑定的前台账号 id
	roles?: Array<{

// 计算属性：普通用户且尚未绑定前台账号时为 true，触发强制绑定流程
get needsAiBind() {
	return this.isAuthed                 // 已登录
		&& !this.isSuperAdmin            // 非超管
		&& !this.userInfo?.aiUserId;     // 尚未绑定
}

// 局部补丁更新用户信息：绑定成功后调用，同时写回 localStorage
patchUserInfo(partial: Partial<UserInfo>) {
	if (!this.userInfo) return;
	this.userInfo = { ...this.userInfo, ...partial };
	localStorage.setItem(USER_INFO_KEY, JSON.stringify(this.userInfo));
}
```

### 4.7 `BindAiUserPage` 绑定页实现（新增）

**改动后** · `apps/frontend/src/views/bind-ai-user/BindAiUserPage.tsx`（当前，核心片段，约 L10-L57）

```typescript
// observer 包裹以响应 store 变化
export const BindAiUserPage = observer(function BindAiUserPage() {
	const { authStore } = useStore();
	const navigate = useNavigate();
	const { token } = theme.useToken();
	const [form] = Form.useForm<{ username: string; email: string }>();
	const [loading, setLoading] = useState(false);

	// 首次进入：三种情况
	useEffect(() => {
		// 1) 未登录：踢回登录页
		if (!authStore.isAuthed) {
			navigate('/login', { replace: true });
			return;
		}
		// 2) 已是超管或已绑定：直接回首页
		if (authStore.isSuperAdmin || authStore.userInfo?.aiUserId) {
			navigate(
				resolveHomePath({
					isSuperAdmin: authStore.isSuperAdmin,
					roles: authStore.userInfo?.roles,
				}),
				{ replace: true },
			);
			return;
		}
		// 3) 普通用户未绑定：预填后台邮箱
		form.setFieldsValue({
			email: authStore.userInfo?.email || '',
		});
	}, []);

	// 提交绑定
	const onFinish = async (values: { username: string; email: string }) => {
		setLoading(true);
		try {
			// 调 /ai-user/bind
			const res = await bindAiUserApi(values);
			// 后端返回的 userInfo 含 aiUserId、最新 roles
			const data = res.data as UserInfo & { aiUserId: number };
			// 回写 store 与 localStorage
			authStore.patchUserInfo({
				aiUserId: data.aiUserId,
				...(data.roles ? { roles: data.roles } : {}),
			});
			message.success('前台账号绑定成功');
			// 绑定完成后跳转到「首个有权限的菜单」
			navigate(
				resolveHomePath({
					isSuperAdmin: false,
					roles: authStore.userInfo?.roles,
				}),
				{ replace: true },
			);
		} finally {
			setLoading(false);
		}
	};
	// JSX 结构省略
});
```

## 5. 兼容性与影响

- 数据库需执行 `ALTER TABLE users ADD aiUserId INT NULL;`（具体迁移脚本按项目迁移规范）。已存在的后台用户 `aiUserId` 默认 `NULL`，行为等同「未绑定」。
- 新增普通用户首次登录会被强制引导到绑定页；超管不受影响。
- 若 `dnhyxc-ai` 业务库未启动，`AiUserService.assertReady()` 会返回 `503 ServiceUnavailable`，绑定失败。

## 6. 风险与回归

- 回归场景建议：
  1. 新注册普通用户首次登录 → 绑定页 → 正确绑定 → 跳转书籍列表。
  2. 绑定页输入错误用户名 / 邮箱不匹配 → 提示友好错误。
  3. 两个后台用户尝试绑定同一前台账号 → 第二次绑定被拒。
  4. 超管访问 `/bind-ai-user` → 自动跳回首页。
  5. 未登录直接访问 `/bind-ai-user` → 跳 `/login`。
  6. 已绑定用户再次访问 `/bind-ai-user` → 跳首页。
