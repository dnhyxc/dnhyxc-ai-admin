# 前台账号换绑与用户名回显

## 1. 背景与目标

后台账号与 dnhyxc-ai 前台账号一对一绑定功能已在 [前台账号绑定](./前台账号绑定.md) 中实现，但存在两个体验缺口：

1. 后台用户绑定错了前台账号时，**没有自助换绑入口**，只能找超管在数据库层修改 `user.aiUserId`。
2. 超管后台的「用户管理」列表只显示「#前台 userId」，**无法直观看到前台用户名**，需要到「AI 用户管理」页交叉查阅。

本篇专题实现以下目标：

- 新增 `/ai-user/current-bind`（GET）供当前登录用户查询自身的前台绑定详情（用户名/邮箱），AI 库不可用时仍能返回 `aiUserId`，保证个人中心页不中断。
- 新增 `/ai-user/rebind`（POST）允许普通用户**在输入当前后台账号密码验证身份后**，用「新前台用户名 + 邮箱」自助换绑；换绑时校验前台账号存在性、邮箱匹配、是否已被他人占用。
- 超管「用户管理」列表对已绑定用户的 `aiUserId`，通过一次批量 `IN (...)` 查询关联 `aiUsername` 并回显为 Tag，替代纯数字 `#id` 展示；AI 库不可用时安全降级为原 `#id` 展示。
- 非超管用户在个人中心看到当前绑定并可发起换绑；超管则在「用户管理」页已经拥有管理员级绑定入口，因此不再重复展示。

## 3. 实现思路

- **接口分层**：查询自身绑定用 GET（幂等、不接收 body），换绑用 POST（含敏感密码字段）。
- **安全校验**：换绑必须附带**当前后台账号密码**（`RebindAiUserDTO.password`），使用与登录一致的 `comparePassword` 比对；避免别人拿着一个已登录的浏览器窗口就能把绑定换掉。
- **邮箱一致性**：沿用首次绑定的规则——前台用户名必须存在且邮箱严格匹配（大小写不敏感），防止胡乱绑到他人的前台账号。
- **唯一绑定约束**：复用既有 `UserService.findByAiUserId(aiUserId, excludeUserId)`，确保新的前台账号未被其它后台账号占用。
- **批量关联查询**：`UserService.findAll` 对分页结果中的 `aiUserId` 去重后，用一条 `IN (...)` 查询从 AI 库取 `(id, username)` 映射，`Map` 构建完成后再逐项回填；避免 N+1 查询。
- **AI 库降级**：AI 库不可用时（`aiDataSource.isInitialized` 为 false 或查询抛错），`findAll` 仅输出 `aiUsername: null`，前台 Tag 层回退显示 `#aiUserId`，不影响用户管理基本能力。
- **前端数据来源**：个人中心的绑定信息有两个可能来源——`authStore.userInfo.aiUsername`（登录时下发）和 `getCurrentAiBindApi`（实时查询）。实时查询优先，用于登录后绑定变更后的即时刷新。

        BadRequestException,
        Injectable,
        ServiceUnavailableException,
} from '@nestjs/common';
// 引入 TypeOrm 的数据源与仓库注入装饰器
import { InjectDataSource, InjectRepository } from '@nestjs/typeorm';
// 引入 TypeOrm 的基础类型与常用操作符
import { DataSource, Like, MoreThanOrEqual, Repository } from 'typeorm';
// 双库连接常量：AI 库对应 DB_CONNECTIONS.AI
import { DB_CONNECTIONS } from '../../database/constants';
// 后台 User 模块的 Service：用来更新 admin 表上的 aiUserId 字段
import { UserService } from '../user/user.service';
// 引入 AI 库的 User 实体
import { AiUser } from './ai-user.entity';
// 首次绑定前台账号使用的 DTO
import { BindAiUserDTO } from './dto/bind-ai-user.dto';

// 标记为 Nest 可注入 Service
@Injectable()
// 导出 AiUserService 类
export class AiUserService {
        // 构造函数：注入三个依赖
        constructor(
                // 注入 AI 库连接的 AiUser 仓库
                @InjectRepository(AiUser, DB_CONNECTIONS.AI)
                private readonly aiUserRepository: Repository<AiUser>,
                // 注入 AI 库的数据源，用于判断连接状态与原生 SQL 查询
                @InjectDataSource(DB_CONNECTIONS.AI)
                private readonly aiDataSource: DataSource,
                // 注入后台的 UserService
                private readonly userService: UserService,
        ) {}

        // 内部断言方法：AI 库未准备好时直接抛出 ServiceUnavailable
        private assertReady() {
                // 数据源未初始化意味着 AI 库连接失败
                if (!this.aiDataSource?.isInitialized) {
                        // 抛出 503，提示配置项
                        throw new ServiceUnavailableException(
                                'AI 业务库未连接，请确认 dnhyxc-ai MySQL 已启动且 AI_DB_* 配置正确',
                        );
                }
        }

        // 按用户名精确查找 AI 库前台用户（返回选中的少量字段）
        findByUsername(username: string): Promise<AiUser | null> {
                // 先断言 AI 库可用
                this.assertReady();
                // 调用 findOne：按 username 精确查询
                return this.aiUserRepository.findOne({
                        // 查询条件：username 严格匹配
                        where: { username },
                        // 查询字段：仅需要的少量列，减少流量
                        select: {
                                id: true,
                                username: true,
                                email: true,
                                createTime: true,
                                isMember: true,
                                membershipType: true,
                                memberExpiresAt: true,
                        },
                });
        }

        // JSDoc：普通用户自助绑定前台账号的业务逻辑
        /**
         * 普通用户自助绑定前台账号：用户名 + 邮箱须与前台账号一致。
         * 绑定后书籍等数据按 aiUserId（前台 user.id）过滤。
         */
        // bindForAdminUser：传入后台账号 id 与 BindAiUserDTO
        async bindForAdminUser(adminUserId: number, dto: BindAiUserDTO) {
                // 断言 AI 库可用
                this.assertReady();
                // 调用 userService.findOne 拿到后台账号
                const adminUser = await this.userService.findOne(adminUserId);
                // 若不存在则抛错
                if (!adminUser) {
                        throw new BadRequestException('用户不存在');
                }

                // 按前台用户名在 AI 库查找该用户
                const aiUser = await this.findByUsername(dto.username.trim());
                // 没找到时提示检查用户名
                if (!aiUser) {
                        throw new BadRequestException('前台账号不存在，请检查用户名');
                }
                // 邮箱匹配：前后台端统一 trim 后，大小写不敏感比较
                if (aiUser.email.toLowerCase() !== dto.email.trim().toLowerCase()) {
                        throw new BadRequestException('前台用户名与邮箱不匹配');
                }

                // 唯一性：该前台账号是否已被「其他后台用户」绑定（排除自己）
                const occupied = await this.userService.findByAiUserId(
                        aiUser.id,
                        adminUserId,
                );
                // 已被占有时抛错
                if (occupied) {
                        throw new BadRequestException('该前台账号已被其他后台用户绑定');
                }

                // 更新 admin 库的 user 表，写入 aiUserId 外键
                await this.userService.update(adminUserId, { aiUserId: aiUser.id });
                // 再次查询最新后台账号信息（保证拿到保存后的实体）
                const updated = await this.userService.findOne(adminUserId);
                // 找不到视为更新失败（防御性编程）
                if (!updated) {
                        throw new BadRequestException('绑定失败');
                }
                // 解构去掉 password 字段，避免返回给前端
                const { password: _, ...userInfo } = updated;
                // 构造返回体：ok=true，附带 aiUsername 与后台账号详情
                return {
                        ok: true,
                        aiUsername: aiUser.username,
                        ...userInfo,
                };
        }

// 引入 TypeOrm 的基础类型与常用操作符

// 双库连接常量：AI 库对应 DB_CONNECTIONS.AI

// 标记为 Nest 可注入 Service
@Injectable()

export class AiUserService {

                                'AI 业务库未连接，请确认 dnhyxc-ai MySQL 已启动且 AI_DB_* 配置正确',
                        );
                }

        // 按用户名精确查找 AI 库前台用户

                // 先断言 AI 库可用
                this.assertReady();
                // 调用 findOne：按 username 精确查询

                this.assertReady();
                // 查询后台账号
                const adminUser = await this.userService.findOne(adminUserId);
                // 若不存在则抛错
                if (!adminUser) {
                        throw new BadRequestException('用户不存在');

                // 在 AI 库按用户名查找前台账号
                const aiUser = await this.findByUsername(dto.username.trim());
                // 没找到时提示
                if (!aiUser) {
                        throw new BadRequestException('前台账号不存在，请检查用户名');
                }
                // 邮箱大小写不敏感匹配
                if (aiUser.email.toLowerCase() !== dto.email.trim().toLowerCase()) {
                        throw new BadRequestException('前台用户名与邮箱不匹配');

                // 唯一性：是否已被其他后台用户绑定
                const occupied = await this.userService.findByAiUserId(
                        aiUser.id,
                        adminUserId,
                );
                if (occupied) {
                        throw new BadRequestException('该前台账号已被其他后台用户绑定');
                }

                // 写入 aiUserId 外键
                await this.userService.update(adminUserId, { aiUserId: aiUser.id });
                // 再查一次拿到最新实体
                const updated = await this.userService.findOne(adminUserId);
                if (!updated) {
                        throw new BadRequestException('绑定失败');
                }
                // 去掉密码字段返回
                const { password: _, ...userInfo } = updated;
                return {
                        ok: true,
                        aiUsername: aiUser.username,
                        ...userInfo,
                };
        }

        // JSDoc：新增方法——查询当前登录后台用户的前台绑定详情
        /**
         * 查询当前登录后台用户的前台账号绑定信息，便于个人中心展示。
         * AI 业务库不可用或记录缺失时仅返回 id，不中断个人中心页。
         */
        // getCurrentBind：返回 { aiUserId, aiUsername, aiEmail }，其中 username/email 可能为 null
        async getCurrentBind(adminUserId: number) {
                // 调用 userService.findOne 查询后台用户实体
                const adminUser = await this.userService.findOne(adminUserId);
                // 后台账号不存在时抛错（通常不应发生）
                if (!adminUser) {
                        throw new BadRequestException('用户不存在');
                }
                // 若后台账号还没绑定前台，直接返回全空（除了 aiUserId:null）
                if (!adminUser.aiUserId) {
                        return { aiUserId: null, aiUsername: null, aiEmail: null };
                }
                // 声明 aiUser 局部变量：存最终拿到的 AI 库前台用户少量字段
                let aiUser: Pick<AiUser, 'id' | 'username' | 'email'> | null = null;
                try {
                        // 尝试查询 AI 库前台用户（取 id、username、email 三个字段）
                        aiUser = await this.aiUserRepository.findOne({
                                where: { id: adminUser.aiUserId },
                                // 仅选三列，降低网络 IO
                                select: { id: true, username: true, email: true },
                        });
                } catch {
                        // AI 库不可用（连接未初始化或 SQL 异常）时置空，不中断页面
                        aiUser = null;
                }
                // 拼装返回：aiUserId 以 admin 库为准（即使 AI 库找不到也保留已绑定的外键）
                return {
                        // 后台记录的 aiUserId
                        aiUserId: adminUser.aiUserId,
                        // AI 库能查到则取 username，否则为 null
                        aiUsername: aiUser?.username ?? null,
                        // AI 库能查到则取 email，否则为 null
                        aiEmail: aiUser?.email ?? null,
                };
        }

        // JSDoc：新增方法——普通用户换绑前台账号
        /**
         * 普通用户换绑前台账号：需校验当前后台账号密码，再按
         * 「存在性 → 邮箱一致 → 未被他人占用 → 写回 aiUserId」完成换绑。
         * 换绑后书籍等数据按新的 aiUserId（前台 user.id）过滤。
         */
        // rebindForAdminUser：接收 RebindAiUserDTO（username/email/password）
        async rebindForAdminUser(adminUserId: number, dto: RebindAiUserDTO) {
                // 断言 AI 库可用（前台账号信息存 AI 库）
                this.assertReady();
                // 查询当前后台用户
                const adminUser = await this.userService.findOne(adminUserId);
                // 找不到时抛错
                if (!adminUser) {
                        throw new BadRequestException('用户不存在');
                }

                // 安全校验：比对用户输入的当前后台密码与数据库 bcrypt 哈希
                const isPasswordValid = await comparePassword(
                        // 用户明文输入的当前后台登录密码
                        dto.password,
                        // 后台库存储的 bcrypt 哈希（带 salt）
                        adminUser.password,
                );
                // 比对失败则阻止换绑
                if (!isPasswordValid) {
                        throw new BadRequestException('当前账号密码错误');
                }

                // 在 AI 库按新的前台用户名精确查找
                const aiUser = await this.findByUsername(dto.username.trim());
                // 找不到时提示（和首次绑定一致）
                if (!aiUser) {
                        throw new BadRequestException('前台账号不存在，请检查用户名');
                }
                // 邮箱大小写不敏感匹配（和首次绑定一致）
                if (aiUser.email.toLowerCase() !== dto.email.trim().toLowerCase()) {
                        throw new BadRequestException('前台用户名与邮箱不匹配');
                }

                // 唯一性：该前台账号是否已被「其他后台账号」绑定（排除自己）
                const occupied = await this.userService.findByAiUserId(
                        aiUser.id,
                        adminUserId,
                );
                // 已被占用则阻止换绑
                if (occupied) {
                        throw new BadRequestException('该前台账号已被其他后台用户绑定');
                }

                // 写入新的 aiUserId 到 admin 库 user 表（和首次绑定用同一 update 方法）
                await this.userService.update(adminUserId, { aiUserId: aiUser.id });
                // 再查一次拿到最新后台账号
                const updated = await this.userService.findOne(adminUserId);
                // 拿不到视为失败
                if (!updated) {
                        throw new BadRequestException('换绑失败');
                }
                // 解构去掉 password，避免泄漏
                const { password: _, ...userInfo } = updated;
                // 返回成功体：ok=true、前台用户名、以及去敏后的后台账号信息
                return {
                        // 成功标记
                        ok: true,
                        // 新绑定的前台用户名，便于前端提示
                        aiUsername: aiUser.username,
                        // 后台账号其余信息（spread 展开）
                        ...userInfo,
                };
        }

        // ...（后续 findAll、count、getHealth、getDashboardStats 未改动，省略）
```

                        aiUsername:
                                u.aiUserId != null ? (aiUsernameMap.get(u.aiUserId) ?? null) : null,
                }));

                // 返回填充好的 viewList 与 total
                return { list: viewList, total };
        }

        // ...（其余方法未改动，省略）
```

**变更摘要**：
- 新增 `UserView` 接口（导出），`findAll` 返回 `UserView[]`，列表接口天然带 `aiUsername`。

                                email: values.email,
                                password: values.password,

                                aiUserId?: number | null;

                } finally {
                        // 解除 loading

                }

## 5. 行为变化与兼容性

| 维度 | 行为 |
|------|------|
| 登录态 | 不受影响；UserInfo 仅多了可选 `aiUsername`，后端即便不下发也不会报错。 |
| 超管用户 | 个人中心**不显示**「前台账号绑定」卡片与换绑入口（超管在用户管理页已有管理员级操作入口）。 |
| 普通用户 | 个人中心新增绑定卡片 + 换绑入口；换绑需输入当前后台密码。 |
| 用户管理列表（超管可见） | 新增 `aiUsername` 回显；AI 库不可用时自动回退为 `#aiUserId`，列表不会空白。 |
| AI 库不可用降级 | `getCurrentBind` 返回 `aiUsername: null`；`findAll` 返回 `aiUsername: null`；换绑会收到 503。均不会抛未捕获异常到页面。 |
| 唯一性约束 | 与首次绑定保持一致：`findByAiUserId(aiUserId, excludeUserId)` 防重复绑定。 |

## 6. 测试与回归建议

1. **普通用户**未绑定**：个人中心显示 `前台用户名：—`，点击「换绑前台账号」流程等价于首次绑定（除需额外输入当前后台密码）。
2. **普通用户已绑定**：个人中心展示已有前台用户名与邮箱，换绑时输入错误的当前后台密码应提示「当前账号密码错误」。
3. 输入存在的前台用户名但邮箱不匹配 → 提示「前台用户名与邮箱不匹配」。
4. 输入已被另一后台账号绑定的前台账号 + 正确邮箱 → 提示「该前台账号已被其他后台用户绑定」。
5. 换绑成功后：个人中心卡片立即刷新为新前台账号信息，前往电子书/知识库等列表，数据按新 aiUserId 过滤。
6. 超管视角：用户管理列表的「关联用户」列在绑定有前台账号的行中显示蓝色 Tag 前台用户名；关掉 AI 数据库重启后端后，同一列回退显示 `#id`，列表其余功能正常。
7. 权限：两个新接口均需 `ADMIN` 或 `USER` 角色；未登录用户应 401。
