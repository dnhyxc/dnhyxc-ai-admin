## 1. 背景与目标

### 1.1 背景（现存问题）
当前 Admin 管理台已具备 AI 用户、AI 日志、AI 电子书等业务库管理能力，但**缺少对 `dnhyxc_ai_db` 业务库中「知识库」核心数据的可视化管理**：
- 运营/审核人员无法通过 Admin 台浏览前台用户上传或生成的知识库条目。
- 发生误删或违规内容时，缺少「删除后可恢复」的软删流程，直接物理删除风险极大。
- 普通 Admin 账号与超级管理员之间没有数据权限隔离，可能导致越权查看/删除他人知识库。
- 前端仅能对接 API，缺少「正常列表 / 回收站」双视图统一管理页面。

### 1.2 目标（交付结果）
本模块落地后，达成以下 5 项能力：
1. **双表只读管理**：后端提供 `knowledge`（主表）与 `knowledge_trash`（回收站表）两张表的分页列表查询接口，支持按 `title` / `author` 关键字模糊筛选。
2. **权限隔离模型**：超级管理员可查看/删除全量数据；普通 Admin 用户仅能操作「自身绑定的前台 aiUserId 所创建」的知识库；未绑定前台账号的普通用户返回空列表。
3. **软删事务机制**：从主表删除条目时，先在同一事务中完整插入回收站（保留原创建/更新时间），再删主表；保证 DB 异常或回滚时不会出现"数据既不在主表也不在回收站"的幽灵删除。
4. **硬删回收站**：提供对回收站条目的永久删除接口，仅作用于回收站表（主表不受影响）。
5. **前端双 Tab 接入**：前端页面在同一视图内切换「知识库列表 / 回收站列表」，顶部提供标题（+作者，超管可见）筛选，行内提供「删除 / 彻底删除」二次确认，分页保持一致。

## 3. 实现思路

### 3.1 双实体设计（主表 `knowledge` + 回收站表 `knowledge_trash`）
- **主表 AiKnowledge**：`id`（UUID 主键）+ `title` / `content` / `author` / `authorId` / `isPublic` + 审计字段 `createdAt` / `updatedAt`；其中 `isPublic` 建立二级索引 `IDX_knowledge_public` 用于后续"公开知识库列表"快速筛选。
- **回收站 AiKnowledgeTrash**：保留主表所有业务字段（title/content/author/authorId）并追加 `originalId`（主表原始 UUID，便于还原）+ `sourceCreatedAt` / `sourceUpdatedAt`（归档时快照）+ `deletedAt`（自动创建时间 = 删除发生时间）。该实体不使用 TypeORM 自带 `@DeleteDateColumn` 软删，而是显式"先插再删"，避免业务侧与框架 SoftRemove 行为耦合。

### 3.2 权限隔离模型（超管看全量 / 普通用户按 `authorId` 过滤）
Controller 层的私有方法 `resolveScope(req)` 统一做两件事：
1. 通过 JWT 解析的 `userId` 调 `UserService.findOne` 查出 Admin 用户关联的 `roles` 与 `aiUserId`。
2. 判断是否含 `Role.ADMIN` 或角色名 `超级管理员`：
   - 超管：`scopeAiUserId = undefined`（SQL 不追加 authorId 过滤，即全量），且允许使用「作者」筛选入参。
   - 普通：`scopeAiUserId = adminUser.aiUserId ?? null`，若为 `null` 则 Service 层直接返回空列表（避免无效 SQL），同时忽略请求中的 `author` 入参（防止越权拉取他人数据）。

### 3.3 软删事务（先插回收站、再删主表、同一事务）
Service 的 `softDelete` 使用 `aiDataSource.transaction(manager => ...)` 保证原子性：
1. `kbRepo.createQueryBuilder` 按 `id` + 可选 `authorId` 查出目标对象；若对象不存在则直接 `return`（幂等，不抛异常）。
2. `trashRepo.insert` 将目标对象完整搬运到回收站：`originalId = target.id`，`sourceCreatedAt/sourceUpdatedAt` 快照。
3. `kbRepo.delete(target.id)` 从主表物理删除。
4. 任一步抛错 → 事务回滚 → 主表保留、回收站无残留 → **一致性**。

### 3.4 通用 `queryList<T>` 抽象（列表/回收站复用）
Service 内部泛型方法 `queryList` 同时服务于：
- `findAll` → 主表，orderBy = `createdAt DESC`
- `findAllTrash` → 回收站，orderBy = `deletedAt DESC`

复用点：
- `scopeAiUserId === null` → 短路返回 `{ list: [], total: 0 }`（未绑定前台账号的普通用户）。
- 统一分页 `take/skip` 计算。
- 统一 title/author 模糊匹配（`LIKE %kw%`）。
- 统一 `getManyAndCount` 返回结构。

### 3.5 前端双 Tab + 筛选模式
- **状态驱动**：单一 `activeTab: 'list' \| 'trash'` 控制 `load()` 选用 `getAiKnowledgeApi` 或 `getAiKnowledgeTrashApi`。
- **筛选差异**：`title` 两 Tab 通用；`author` 输入框仅在 `isAdmin === true` 时渲染（普通用户服务端已忽略该参数，UI 层也隐藏，避免误导）。
- **columns 差异**：列表 Tab 显示 `isPublic` 标签 + `createdAt/updatedAt`；回收站 Tab 显示 `sourceCreatedAt/sourceUpdatedAt/deletedAt`，并将操作按钮文案变为「彻底删除」，Popconfirm 提示语更强烈（"不可恢复"）。
- **错误兜底**：AI 业务库不可用时 `Alert` 顶部显示错误，并强制 `locale.emptyText = ' '` 避免 antd 默认 Empty 与 Alert 信息重复。

### 3.6 模块接入要点（Nest 模块、路由、菜单、种子）
1. **Nest 模块注册**：`app.module.ts` 中将 AiKnowledgeModule 放入 `AI_DB_ENABLED` 条件数组，保证关闭 AI 库开关时不会在应用启动阶段尝试连接。
2. **TypeORM 实体接入**：`typeorm-ai.config.ts` 的 `entities` 注册两个新实体，否则 `TypeOrmModule.forFeature` 会在连接建立时报错「Repository 未注册」。
3. **前端路由注册**：`router/index.tsx` 中 children 按"AI 域"顺序排列：`ai-users` → `ai-ebooks` → `ai-knowledge` → `ai-logs`；路径 `/ai-knowledge` 对应 `AiKnowledgePage`。
4. **API 常量 & 调用函数**：`service/api.ts` 集中管理 URL；`service/index.ts` 输出命名函数，供页面 `import` 使用，确保 HTTP 请求统一走 `http` 封装（含 JWT 注入/错误拦截/silent 静默）。
5. **菜单 & 种子**（**本次改动清单未直接列出，但必须配套完成**）：在 `router/menu.ts` 中注册该路由对应的菜单节点（order/权限编码 `admin:ai-knowledge:view` 等），并在 `seed.service.ts` 的管理员/普通管理员种子角色中分配该菜单权限。

注：本文件为本次改动纯新增，基线版本中不存在。
**改动后** · `apps/backend/src/services/ai-knowledge/ai-knowledge.entity.ts`（完整文件）

```typescript
// 从 typeorm 导入装饰器集合：列定义、创建/更新时间戳、实体声明、索引、主键自增列
import {
        // 字段列装饰器，用于映射 MySQL 列
        Column,
        // 自动填充"创建时间"的特殊列装饰器
        CreateDateColumn,
        // 声明该类为 TypeORM 实体
        Entity,
        // 声明索引装饰器，此处用于对 isPublic 字段建二级索引以加速公开列表查询
        Index,
        // 主键列装饰器，uuid 策略会生成字符串型 UUID 作为主键
        PrimaryGeneratedColumn,
        // 自动填充"更新时间"的特殊列装饰器
        UpdateDateColumn,
// import 语句闭合
} from 'typeorm';

// 声明该类映射到数据库的 knowledge 表，并对 isPublic 字段建立名为 IDX_knowledge_public 的索引
@Entity({ name: 'knowledge' })
// 二级索引：按 isPublic 快速过滤公开/私有知识库
@Index('IDX_knowledge_public', ['isPublic'])
// 导出实体类，供 TypeOrmModule.forFeature 注册与 Service 注入 Repository
export class AiKnowledge {
        // 声明 UUID 主键，生成策略由数据库层或 typeorm uuid 算法负责
        @PrimaryGeneratedColumn('uuid')
        // 主键字段：知识库唯 ID，前端以该 id 为删除/行 key
        id: string;

        // title 列定义：text 类型（长文本），允许为 NULL 以兼容未填写标题的知识库
        @Column('text', { nullable: true })
        // 标题字段：前台展示的知识库标题
        title: string | null;

        // content 列定义：longtext 类型（超长正文），允许 NULL 以兼容空草稿
        @Column({ type: 'longtext', nullable: true })
        // 正文字段：知识库 markdown 或富文本源内容
        content: string;

        // author 列：varchar 字符串，允许 NULL 以兼容匿名上传
        @Column('varchar', { nullable: true })
        // 作者名称：前台用户昵称或展示名，仅用于列表展示，不作为关联键
        author: string | null;

        // authorId 列：int 整数，允许 NULL；对应 ai_user 表 id（前台用户）
        @Column('int', { nullable: true })
        // 作者 ID：用于权限隔离—— 普通 Admin 仅能操作 authorId === 自己绑定 aiUserId 的行
        authorId: number | null;

        // isPublic 列：boolean 类型，DB 列名 is_public，默认 false（私有）
        @Column({ name: 'is_public', type: 'boolean', default: false })
        // 是否公开：公开知识库可被前台游客或所有用户看到；默认私有
        isPublic!: boolean;

        // createdAt：创建时间戳，列名 created_at，timestamp 类型，插入时自动赋值
        @CreateDateColumn({ name: 'created_at', type: 'timestamp' })
        // 创建时间：列表 Tab 默认按该字段降序展示最新条目
        createdAt: Date;

        // updatedAt：更新时间戳，列名 updated_at，timestamp 类型，每次 UPDATE 自动赋值
        @UpdateDateColumn({ name: 'updated_at', type: 'timestamp' })
        // 更新时间：用于展示最近一次内容被修改的时间
        updatedAt: Date;
// 实体类闭合
}
```

### 4.2 纯新增：AiKnowledgeTrash 回收站实体

注：本文件为本次改动纯新增，基线版本中不存在。
**改动后** · `apps/backend/src/services/ai-knowledge/ai-knowledge-trash.entity.ts`（完整文件）

```typescript
// 从 typeorm 导入所需装饰器：普通列、创建时间、实体声明、主键自增
import {
        // 列装饰器，用于定义各类 DB 字段
        Column,
        // 创建时间戳列，deletedAt 采用该装饰器自动记录"进入回收站时间=删除发生时间"
        CreateDateColumn,
        // 实体声明装饰器，绑定到 knowledge_trash 表
        Entity,
        // UUID 主键列装饰器
        PrimaryGeneratedColumn,
// import 语句结束
} from 'typeorm';

// 声明该实体映射到 knowledge_trash 表
@Entity({ name: 'knowledge_trash' })
// 导出回收站实体类，供 Service 注入 TrashRepository 使用
export class AiKnowledgeTrash {
        // UUID 主键：回收站自身的唯一 ID（与主表 originalId 区分，支持同一 originalId 多次删除归档）
        @PrimaryGeneratedColumn('uuid')
        // 回收站条目 ID：硬删接口 / 前端行 key 使用该字段
        id: string;

        // originalId：原 knowledge 主表 id 快照；DB 列名 original_id，UUID 类型字符串
        @Column('uuid', { name: 'original_id' })
        // 原始主表 ID：未来"从回收站还原"功能据此回写到 knowledge 表
        originalId: string;

        // title 列：text 类型，允许 NULL；与主表 title 一致
        @Column('text', { nullable: true })
        // 归档时的标题快照：防止主表已删但回收站仍需展示标题
        title: string | null;

        // content 列：longtext 类型，允许 NULL；完整保留被删时的正文
        @Column({ type: 'longtext', nullable: true })
        // 归档时的正文快照：未来可还原或作为审计依据
        content: string | null;

        // author 列：varchar 类型，允许 NULL；作者昵称快照
        @Column('varchar', { nullable: true })
        // 归档时的作者昵称快照
        author: string | null;

        // authorId 列：int 类型，允许 NULL；前台用户 id 快照，用于权限隔离
        @Column('int', { nullable: true })
        // 归档时的作者 ID：普通 Admin 只能硬删 authorId === 自身 aiUserId 的回收站条目
        authorId: number | null;

        // sourceCreatedAt：主表创建时间的归档快照；列名 source_created_at，timestamp 类型，允许 NULL
        @Column('timestamp', { name: 'source_created_at', nullable: true })
        // 主表原始创建时间：回收站 Tab 展示"原创建时间"列
        sourceCreatedAt: Date | null;

        // sourceUpdatedAt：主表更新时间的归档快照；列名 source_updated_at，timestamp 类型，允许 NULL
        @Column('timestamp', { name: 'source_updated_at', nullable: true })
        // 主表原始更新时间：回收站 Tab 展示"原更新时间"列
        sourceUpdatedAt: Date | null;

        // deletedAt：进入回收站的时间；使用 CreateDateColumn 自动在 INSERT 时写入当前时间
        @CreateDateColumn({ name: 'deleted_at', type: 'timestamp' })
        // 删除时间：回收站 Tab 默认按该字段降序展示（最近被删的在前）
        deletedAt: Date;
// 回收站实体类闭合
}
```

// 从 @nestjs/common 导入 Injectable 装饰器（声明可注入）+ ServiceUnavailableException（AI 库未连接 503）
import { Injectable, ServiceUnavailableException } from '@nestjs/common';
// 从 @nestjs/typeorm 导入装饰器：注入 Repository / 注入 DataSource
import { InjectDataSource, InjectRepository } from '@nestjs/typeorm';
// typeorm 基础类型：DataSource 用于获取事务管理器；Repository 即仓库类
import { DataSource, Repository } from 'typeorm';
// 导入 AI 连接名常量
import { DB_CONNECTIONS } from '../../database/constants';
// 导入主表实体
import { AiKnowledge } from './ai-knowledge.entity';
// 导入回收站实体
import { AiKnowledgeTrash } from './ai-knowledge-trash.entity';

// 声明该 Service 可被 Nest DI 注入
@Injectable()
// 导出 Service 类，供 Controller 与模块使用
export class AiKnowledgeService {
        // 构造函数：使用装饰器注入两个 Repository 与一个 AI 连接 DataSource
        constructor(
                // 注入 AiKnowledge 主表 Repository，指定 AI 连接
                @InjectRepository(AiKnowledge, DB_CONNECTIONS.AI)
                // 主表仓库私有只读成员
                private readonly knowledgeRepository: Repository<AiKnowledge>,
                // 注入回收站 Repository，指定 AI 连接
                @InjectRepository(AiKnowledgeTrash, DB_CONNECTIONS.AI)
                // 回收站仓库私有只读成员
                private readonly knowledgeTrashRepository: Repository<AiKnowledgeTrash>,
                // 注入 AI 连接对应的 DataSource：用于事务与连接状态检查
                @InjectDataSource(DB_CONNECTIONS.AI)
                // DataSource 私有成员
                private readonly aiDataSource: DataSource,
        // 构造函数结束
        ) {}

        // 私有断言方法：确保 AI 数据源可用；不可用立即抛 503，避免后续 SQL 抛出更晦涩的 connection destroyed
        private assertReady() {
                // 判空 + isInitialized；未初始化说明 AI_DB 开关关闭或连接失败
                if (!this.aiDataSource?.isInitialized) {
                        // 抛 503 异常，并给出排查指引文案
                        throw new ServiceUnavailableException(
                                'AI 业务库未连接，请确认 dnhyxc-ai MySQL 已启动且 AI_DB_* 配置正确',
                        );
                }
        }

        // 泛型查询方法：列表/回收站都使用该方法构造 QueryBuilder 并分页返回
        // 泛型 T 必须带 authorId 字段（因为权限过滤需要）
        private async queryList<T extends { authorId: number | null }>(
                // 要查询的 Repository：主表/回收站任一
                repo: Repository<T>,
                // 查询参数：分页 + 关键字 + 权限过滤
                query: {
                        // 可选页号
                        pageNo?: number;
                        // 可选每页条数
                        pageSize?: number;
                        // 可选标题模糊匹配
                        title?: string;
                        // 可选作者模糊匹配
                        author?: string;
                        // 可选权限过滤：undefined=超管；number=按 authorId 过滤；null=未绑定前台账号，短路返回空
                        scopeAiUserId?: number | null;
                },
                // 排序字段名：主表默认 createdAt；回收站默认 deletedAt
                orderByField: string = 'createdAt',
        // 方法签名结束
        ) {
                // 短路：scopeAiUserId === null 说明普通用户未绑定前台账号，直接空列表避免无意义 SQL
                if (query.scopeAiUserId === null) {
                        // 返回空集合 + 总数 0
                        return { list: [], total: 0 };
                }

                // 页号：缺省第 1 页
                const pageNo = query.pageNo || 1;
                // 每页大小：缺省 20 条
                const pageSize = query.pageSize || 20;

                // 构建 QueryBuilder，别名 kb（knowledge base 的缩写）
                const qb = repo
                        // 用别名 kb 创建查询构建器
                        .createQueryBuilder('kb')
                        // 按指定字段倒序：列表默认新→旧
                        .orderBy(`kb.${orderByField}`, 'DESC')
                        // LIMIT：取 pageSize 条
                        .take(pageSize)
                        // OFFSET：(pageNo-1)*pageSize 条之前的跳过
                        .skip((pageNo - 1) * pageSize);

                // 若 scopeAiUserId 为具体数字（普通用户已绑定前台账号）则追加 authorId 过滤
                if (query.scopeAiUserId != null) {
                        // andWhere：kb.authorId = :aiUserId 命名参数，防止 SQL 注入
                        qb.andWhere('kb.authorId = :aiUserId', {
                                // 参数赋值
                                aiUserId: query.scopeAiUserId,
                        // 参数对象闭合
                        });
                }
                // 若传入 title 关键字：LIKE 模糊匹配
                if (query.title) {
                        // kb.title LIKE '%title%'
                        qb.andWhere('kb.title LIKE :title', { title: `%${query.title}%` });
                }
                // 若传入 author 关键字：LIKE 模糊匹配作者昵称
                if (query.author) {
                        // kb.author LIKE '%author%'
                        qb.andWhere('kb.author LIKE :author', { author: `%${query.author}%` });
                }

                // 同时执行 getMany（当前页列表）与 getCount（总数）并解构
                const [list, total] = await qb.getManyAndCount();
                // 返回 {list, total} 统一分页结构：前端直接用 total 做分页
                return { list, total };
        }

        // 主表分页查询：对外暴露给 Controller
        async findAll(query: {
                // 可选页号
                pageNo?: number;
                // 可选每页条数
                pageSize?: number;
                // 可选标题
                title?: string;
                // 可选作者
                author?: string;
                // 可选权限过滤
                scopeAiUserId?: number | null;
        }) {
                // 先断言 AI 库已连接
                this.assertReady();
                // 复用通用 queryList：查主表仓库，默认按 createdAt 倒序
                return this.queryList(this.knowledgeRepository, query);
        }

        // 回收站分页查询：对外暴露给 Controller
        async findAllTrash(query: {
                // 可选页号
                pageNo?: number;
                // 可选每页条数
                pageSize?: number;
                // 可选标题
                title?: string;
                // 可选作者
                author?: string;
                // 可选权限过滤
                scopeAiUserId?: number | null;
        }) {
                // 先断言 AI 库已连接
                this.assertReady();
                // 复用通用 queryList：查回收站仓库，按 deletedAt 倒序展示最近被删的
                return this.queryList(this.knowledgeTrashRepository, query, 'deletedAt');
        }

        // 可选暴露：简单计数接口；未来 Dashboard 模块统计"知识库总数"时可复用
        async count() {
                // 先断言 AI 库已连接
                this.assertReady();
                // 主表 count(*)
                return this.knowledgeRepository.count();
        }

        // 软删事务：把主表条目搬运到回收站后删除主表行；scopeAiUserId 非超管必须传
        async softDelete(id: string, scopeAiUserId?: number | null) {
                // 先断言 AI 库已连接
                this.assertReady();
                // 用 AI 连接开启事务：内部任一抛错全部回滚
                await this.aiDataSource.transaction(async (manager) => {
                        // 从事务管理器获取主表 Repository（事务上下文）
                        const kbRepo = manager.getRepository(AiKnowledge);
                        // 从事务管理器获取回收站 Repository（事务上下文）
                        const trashRepo = manager.getRepository(AiKnowledgeTrash);

                        // 构建查询：按 id 定位；若 scopeAiUserId 非空则追加 authorId 条件（越权保护）
                        const qb = kbRepo.createQueryBuilder('kb').where('kb.id = :id', { id });
                        // 普通用户：只允许删自己创建的
                        if (scopeAiUserId != null) {
                                // andWhere：authorId = :aiUserId
                                qb.andWhere('kb.authorId = :aiUserId', { aiUserId: scopeAiUserId });
                        }
                        // 查询目标对象：事务内 select，保证读一致
                        const target = await qb.getOne();
                        // 目标不存在（已删 / id 错 / 越权）则静默 return，保持幂等不抛错
                        if (!target) return;

                        // 第 1 步：向回收站 INSERT 完整快照（必须先插，防止删完后事务崩导致丢数据）
                        await trashRepo.insert({
                                // originalId：归档主表的 UUID
                                originalId: target.id,
                                // 标题快照
                                title: target.title,
                                // 正文快照
                                content: target.content,
                                // 作者昵称快照
                                author: target.author,
                                // 作者 ID 快照：权限还原/过滤用
                                authorId: target.authorId,
                                // 主表原始创建时间归档
                                sourceCreatedAt: target.createdAt,
                                // 主表原始更新时间归档
                                sourceUpdatedAt: target.updatedAt,
                        // insert 对象结束
                        });
                        // 第 2 步：删除主表行；事务提交才会真正持久化
                        await kbRepo.delete(target.id);
                // 事务回调结束
                });
        // softDelete 方法结束
        }

        /**
         * 永久删除回收站中的知识库条目
         * @param id - 回收站中条目的ID
         * @param scopeAiUserId - 可选，限制操作权限的用户ID，仅允许删除该用户创建的条目
         */
        // 硬删回收站条目：非事务（仅对回收站表单条 DELETE），幂等，不存在则静默
        async hardDeleteTrash(id: string, scopeAiUserId?: number | null) {
                // 先断言 AI 库已连接
                this.assertReady();
                // 用回收站仓库构建查询：按 id + 可选 authorId 定位目标
                const qb = this.knowledgeTrashRepository
                        // 查询构建器别名 kb
                        .createQueryBuilder('kb')
                        // id 条件
                        .where('kb.id = :id', { id });
                // 普通用户：只允许硬删自己归档的条目
                if (scopeAiUserId != null) {
                        // andWhere：authorId = :aiUserId
                        qb.andWhere('kb.authorId = :aiUserId', { aiUserId: scopeAiUserId });
                }
                // 查询目标对象
                const target = await qb.getOne();
                // 目标不存在：静默返回，避免重复删除报错
                if (!target) return;
                // 真正物理删除回收站行；deletedAt / originalId / 快照一并清除
                await this.knowledgeTrashRepository.delete(target.id);
        }
// Service 类闭合
}

// 工具函数：将后端返回的 ISO 字符串格式化为本地 YYYY-MM-DD HH:mm:ss；空值返回 '—'
function formatTime(v?: string) {
        // 入参为空 → 直接返回 '—' 占位
        if (!v) return '—';
        // 尝试解析为 Date 对象
        const d = new Date(v);
        // 解析失败（非法字符串）→ 原样回退展示
        if (Number.isNaN(d.getTime())) return v;
        // 二位补零工具：月/日/时/分/秒都需补零
        const p = (n: number) => String(n).padStart(2, '0');
        // 按 YYYY-MM-DD HH:mm:ss 拼接；注意 getMonth() 从 0 开始需 +1
        return `${d.getFullYear()}-${p(d.getMonth() + 1)}-${p(d.getDate())} ${p(d.getHours())}:${p(d.getMinutes())}:${p(d.getSeconds())}`;
}

        // 私有 logger 实例，分类为 TypeOrmAiConfigService，便于日志过滤
        private readonly logger = new Logger(TypeOrmAiConfigService.name);
        // 构造函数注入 ConfigService
        constructor(private readonly configService: ConfigService) {}
        // 实现 TypeOrmOptionsFactory 接口方法：返回 TypeORM 连接 options
        createTypeOrmOptions(): TypeOrmModuleOptions {
                // 读取 AI_DB_ENABLED，默认 true（未配置视为开启）
                const enabled = parseBoolean(this.configService.get(AiDbEnum.AI_DB_ENABLED), true);
                // 读取 AI_DB_POOL_SIZE，默认 5；NaN 时回落 5

                return {

                        name: 'ai',

                        type: 'mysql',

## 5. 兼容性与影响

### 5.1 权限模型兼容
- 依赖 JWT 守卫解析出的 `userId`，并进一步查 `UserService.findOne(userId).roles` 与 `.aiUserId`。若旧版种子未给普通 USER 角色分配 `ai-knowledge` 菜单权限，仅会导致菜单不显示，但直接访问 URL 时会因 `@Roles(ADMIN, USER)` 已授权而进入页面（权限由角色菜单 + @Roles 双层控制，两者需一致），**建议同步在种子中给 USER 角色分配菜单并绑定正确的权限编码**。
- 超管判定使用「`r.id === Role.ADMIN || r.name === '超级管理员'`」双重判断，兼容因历史迁移导致 id=1 不一定等于超级管理员的情况。

### 5.2 `AI_DB_ENABLED` 开关兼容
- 若 `AI_DB_ENABLED=false`，整个 `AiKnowledgeModule` 不会被 `imports`，启动不报错；但前端路由仍会注册 `/ai-knowledge` 页面，访问该页面会触发 `fetch` 报 404 → `catch` 分支走 `Alert` 提示，无白屏。**菜单种子应同步以 AI 域可见性控制（可选）**。

### 5.3 软删一致性
- 软删全程走 `aiDataSource.transaction`：若"插入回收站成功、删除主表失败"，事务回滚后回收站不留脏数据；反之"插回收站失败"时直接回滚、主表也不删。
- 同一 id 重复软删时，第二次事务查不到 `target` 直接 `return`，幂等，不抛错；前端刷新后当前页无该条，符合预期。

### 5.4 未绑 `aiUserId` 的普通用户
- `resolveScope` 返回 `scopeAiUserId = null`；Service 层 `queryList` 首行 `scopeAiUserId === null → { list: [], total: 0 }` 短路返回，无 SQL 执行；前端页面顶部文案提示「尚未绑定前台账号」，引导用户先去 BindAiUserPage 绑定。

### 5.5 UUID 兼容
- 主表与回收站均使用 UUID 主键，不依赖自增 ID 顺序；回收站使用独立 `id` + `originalId` 双 ID 结构，同一主表条目若被删除→还原→再删除多次，也会在回收站产生多行独立记录，不冲突。

## 6. 验收清单

### 6.1 后端接口（6 项）
- [ ] **列表接口**：`GET /ai-knowledge/getKnowledgeBases?pageNo=1&pageSize=20` 返回 `{ code, data: { list, total }, message }`，`list` 为 knowledge 表行，按 `createdAt DESC`。
- [ ] **回收站接口**：`GET /ai-knowledge/getKnowledgeTrash?pageNo=1&pageSize=20` 返回回收站列表，按 `deletedAt DESC`。
- [ ] **模糊搜索**：传 `title=xx` 返回 `kb.title LIKE '%xx%'`；超管传 `author=yy` 追加 `kb.author LIKE '%yy%'`；普通用户传 `author` 不生效（服务端忽略）。
- [ ] **软删接口**：`DELETE /ai-knowledge/deleteKnowledge/:id` 后，knowledge 表少一行，knowledge_trash 表多一行且 `originalId = :id`，`sourceCreatedAt/sourceUpdatedAt` 与原记录一致。
- [ ] **硬删接口**：`DELETE /ai-knowledge/deleteKnowledgeTrash/:id` 后，回收站对应行被物理删除；knowledge 表无影响。
- [ ] **AI 库不可用**：关闭 MySQL 或 AI_DB_ENABLED=false 时，4 个接口都返回 503（列表）或 503（删），异常消息为中文「AI 业务库未连接…」。

### 6.2 Service 层（5 项）
- [ ] **权限短路**：`scopeAiUserId = null` 时 `findAll / findAllTrash` 直接 `{ list: [], total: 0 }`，不执行任何 SQL。
- [ ] **软删幂等**：对同一 id 连续两次 softDelete，第二次不报错；DB 中回收站也不会重复插入（因为第二次 `target` 已不在 knowledge）。
- [ ] **软删越权**：普通用户 scopeAiUserId=100 删 authorId=200 的记录 → `target` 查不到 → 静默 return，无副作用。
- [ ] **硬删越权**：普通用户 scopeAiUserId=100 硬删 authorId=200 的回收站行 → 无副作用；超管能删任意 authorId 行。
- [ ] **事务一致性**：在 softDelete 中 `trashRepo.insert` 之后、`kbRepo.delete` 之前模拟抛错（或断点 drop 连接），回滚后 knowledge 行仍存在，回收站无新增残留。

### 6.3 前端页面（8 项）
- [ ] **挂载默认值**：首次进入 `/ai-knowledge` 自动请求 `getKnowledgeBases({ pageNo:1, pageSize:20, title:undefined, author:undefined })`。
- [ ] **双 Tab 切换**：从「知识库列表」切到「回收站列表」自动请求 `getKnowledgeTrash({ pageNo:1, ... })` 并重置到第 1 页，保留标题筛选；反之亦然。
- [ ] **超管作者筛选**：超管登录时，工具栏显示「作者」输入框，输入关键词后点击「查询」会在请求中携带 `author=xx`；普通用户不渲染该输入框。
- [ ] **列分叉正确**：列表 Tab columns 含「公开 / 创建时间 / 更新时间」；回收站 Tab columns 含「原创建时间 / 原更新时间 / 删除时间 / 彻底删除」。
- [ ] **软删二次确认**：点击「删除」→ 弹出 Popconfirm「确认删除？将移入回收站」→ 确认后 toast「已删除」并自动刷新当前页。
- [ ] **硬删二次确认**：回收站 Tab 点击「彻底删除」→ Popconfirm「确认彻底删除？不可恢复」→ 确认后当前行消失。
- [ ] **错误兜底**：在 AI 库关闭情况下进入页面，顶部 Alert 出现黄色警告文案；表格 `emptyText` 为空（无重复 Empty 图标），总数字段正确。

### 6.4 权限（4 项）
- [ ] **未登录访问**：不带 Token 调 4 个接口 → 401。
- [ ] **普通 USER 角色访问**：带合法 USER Token 调 4 个接口 → 200，但查询与删除均限 scopeAiUserId 范围内。
- [ ] **超管看全量**：超管 Token 请求列表不传 author → 返回所有 authorId 的行；传 author 模糊筛选生效；软删/硬删 authorId 非自己的行成功。
- [ ] **未绑定前台账号的普通 USER**：列表接口返回空；页面展示「尚未绑定前台账号」，工具栏仅显示标题输入框。
