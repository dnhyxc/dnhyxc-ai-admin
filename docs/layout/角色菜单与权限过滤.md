# 角色菜单与权限过滤

## 1. 背景与目标

后台此前所有登录用户（超管 / 普通用户）共用同一套侧栏菜单与路由，普通用户仍能看到「管理员、角色、菜单、后台日志」等超管入口，只能靠后端 `@Roles` 注解兜底拒绝请求。用户体验差且容易暴露敏感页面。本专题实现：

- 后端在登录响应中下发「当前用户所有角色可见的菜单」（`roles[].menus[]`）。
- 前端基于下发菜单做**侧栏过滤**与**路由访问校验**，超管保持全量，普通用户仅可见其角色菜单。
- 新增 `profile` 路由对所有登录用户开放（即使普通用户角色未绑定该菜单），便于自助修改密码。
- 新增「绑定前台账号」流程与首页分流，与菜单权限联动。

## 2. 改动范围

- `apps/backend/src/services/auth/auth.service.ts`（`login` 返回 `roles.menus`）
- `apps/backend/src/services/auth/auth.controller.ts`（`profile` 返回 `roles.menus`）
- `apps/backend/src/services/seed/seed.service.ts`（菜单表新增 `/ai-ebooks` 条目；普通用户角色菜单绑定 `/ai-ebooks`）

- 多个控制器 `@Roles(Role.ADMIN, Role.USER)` → `@Roles(Role.ADMIN)`（`ai-logs`、`dashboard`、`logs`、`menus`、`roles`、`user`）

- `apps/frontend/src/router/index.tsx`（`RequireAiBound`、`HomeIndex`、`profile` 路由）

## 3. 实现思路

1. 数据通路：`SeedService` 在启动时写入菜单表并为普通用户角色绑定 `['/ai-ebooks']`，`AuthService.login` 通过 `userService.findOne`（带 `roles: { menus: true }`）把完整菜单下发给前端。
2. 前端侧栏：`AdminLayout` 中用 `collectAllowedPaths + filterMenuItems` 过滤 `menuItems`，超管不过滤。
3. 前端路由守卫：`AdminLayout` 的 `useEffect` 里用 `canAccessPath` 判断当前路径是否在允许列表里，不在则跳转到首个允许路径。`/profile` 与 `profile/*` 额外放行，便于修改密码。
4. 首页分流：`HomeIndex` 与 `LoginPage.goAfterAuth` 用 `resolveHomePath` 计算落点，超管进 `/`（仪表盘），普通用户进首个有权限的菜单，兜底 `/ai-ebooks`。
5. 后端接口级权限同步收紧：`ai-logs`、`dashboard`、`logs`、`menus`、`roles`、`user` 的控制器 `@Roles` 调整为仅 `ADMIN`，避免普通用户绕过前端直接请求。

### 4.2 `ensureUserRole` 给普通用户角色绑定菜单

**改动前** · `apps/backend/src/services/seed/seed.service.ts`（基线，无 `ensureUserRole` 方法，普通用户角色在别处创建，且未绑定菜单）

**改动后** · `apps/backend/src/services/seed/seed.service.ts`（当前，`ensureUserRole`，约 L112-L156）

```typescript
// 普通用户：仅「书籍列表」菜单
private async ensureUserRole() {
	// 查出 USER_MENU_PATHS 对应的菜单实体（['/ai-ebooks']）
	const userMenus = await this.menusRepo
		.createQueryBuilder('m')
		.where('m.path IN (:...paths)', { paths: USER_MENU_PATHS })
		.getMany();

	// 查普通用户角色：按 id=2 或 name='普通用户' 兼容
	let userRole =
		(await this.rolesRepo.findOne({
			where: { id: 2 },
			relations: ['menus'],
		})) ||
		(await this.rolesRepo.findOne({
			where: { name: '普通用户' },
			relations: ['menus'],
		}));

	// 首次：创建角色并绑定书籍列表菜单
	if (!userRole) {
		userRole = await this.rolesRepo.save(
			this.rolesRepo.create({
				name: '普通用户',
				description: '仅可查看关联前台账号的书籍列表',
				menus: userMenus,
			}),
		);
		this.logger.log('已种子普通用户角色');
		return;
	}

	// 已存在：对比菜单是否一致，不一致则同步
	const want = new Set(userMenus.map((m) => m.id));
	const have = new Set((userRole.menus || []).map((m) => m.id));
	const same = want.size === have.size && [...want].every((id) => have.has(id));
	if (!same) {
		userRole.menus = userMenus;
		userRole.description = '仅可查看关联前台账号的书籍列表';
		await this.rolesRepo.save(userRole);
		this.logger.log('已同步普通用户角色菜单');
	}
}
```

**变更摘要**：普通用户角色被显式绑定 `['/ai-ebooks']`，登录响应会把该菜单路径下发给前端。

### 4.5 前端 `menu.ts` 新增权限计算工具

```typescript
// 从角色菜单集合提取可访问 path，返回 Set 便于快速查找
export function collectAllowedPaths(
	roles?: Array<{ menus?: Array<{ path?: string }> }>,
): Set<string> {
	const paths = new Set<string>();
	for (const role of roles || []) {
		for (const menu of role.menus || []) {
			if (menu.path) paths.add(menu.path);   // 累加所有角色的菜单
		}
	}
	return paths;
}

// 按角色菜单过滤侧栏 items；超管直接返回全量
export function filterMenuItems(
	items: MenuEntry[],
	opts: { isSuperAdmin: boolean; allowedPaths: Set<string> },
): MenuEntry[] {
	if (opts.isSuperAdmin) return items;         // 超管不做过滤
	const result: MenuEntry[] = [];
	for (const item of items) {
		if ('children' in item && item.children) {
			// 分组：仅保留在 allowedPaths 中的子项
			const children = item.children.filter((c) =>
				opts.allowedPaths.has(c.path),
			);
			if (children.length) {
				result.push({ ...item, children });   // 保留有子项的分组
			}
		} else if ('path' in item && opts.allowedPaths.has(item.path)) {
			// 顶层叶子节点（如仪表盘）命中则保留
			result.push(item);
		}
	}
	return result;
}

// 判断某路径当前用户是否可访问
export function canAccessPath(
	pathname: string,
	opts: { isSuperAdmin: boolean; allowedPaths: Set<string> },
) {
	if (opts.isSuperAdmin) return true;          // 超管全部放行
	if (pathname === '/profile' || pathname.startsWith('/profile/')) return true;  // profile 路由放行
	if (pathname === '/') return opts.allowedPaths.has('/');  // 仪表盘需显式授权
	// 规则：allowedPaths 任一路径是 pathname 的前缀则放行
	return [...opts.allowedPaths].some(
		(p) => p !== '/' && pathname.startsWith(p),
	);
}

// 登录后首页：超管进仪表盘，普通用户进首个有权限菜单
export function resolveHomePath(opts: {
	isSuperAdmin: boolean;
	roles?: Array<{ menus?: Array<{ path?: string }> }>;
}) {
	if (opts.isSuperAdmin) return '/';
	const paths = collectAllowedPaths(opts.roles);
	// 首个有权限的菜单路径；兜底 /ai-ebooks
	return [...paths][0] || '/ai-ebooks';
}
```

**变更摘要**：四个函数覆盖「取路径 → 过滤侧栏 → 守卫判断 → 首页分流」，集中在 `menu.ts` 便于复用。

// 1) 基于用户信息计算允许的路径集合
const allowedPaths = collectAllowedPaths(authStore.userInfo?.roles);
// 用排序后的路径拼接 key，作为 useEffect 依赖，避免每次 render 都触发
const allowedPathKey = [...allowedPaths].sort().join(',');
// 过滤后的侧栏项
const visibleMenus = filterMenuItems(menuItems, {
	isSuperAdmin: authStore.isSuperAdmin,
	allowedPaths,
});
// ...
// 2) 访问守卫：当前路径不在允许范围内则跳转到首个允许路径
useEffect(() => {
	const paths = new Set(
		allowedPathKey ? allowedPathKey.split(',') : [],
	);
	if (
		canAccessPath(location.pathname, {
			isSuperAdmin: authStore.isSuperAdmin,
			allowedPaths: paths,
		})
	) {
		return;   // 合法路径，无需跳转
	}
	// 非法路径：跳到首个允许路径；若无则回登录
	const fallback = [...paths][0] || '/login';
	navigate(fallback, { replace: true });
}, [location.pathname, authStore.isSuperAdmin, allowedPathKey, navigate]);

// 3) 侧栏渲染改用 visibleMenus
visibleMenus.map((item) => { ... });

## 5. 兼容性与影响

- 旧版角色（`super_admin` / `user`）的 `roles.menus` 在首次启动时由 `SeedService.ensureUserRole` 自动补齐；已在生产的数据库需重启应用以触发补种逻辑。
- 新增普通用户登录后只能看到「书籍列表」侧栏，其他入口被前端过滤 + 后端拒绝双重保护。
- `profile` 路由对所有登录用户可用，用于修改密码，即使该用户角色未绑定该菜单。

## 6. 风险与回归

- 回归建议：
  1. 超管登录 → 所有菜单可见 → 各页面可访问。
  2. 普通用户登录 → 仅见「书籍列表」→ 访问 `/users` 等被自动跳回 `/ai-ebooks`。
  3. 普通用户直接访问 `/profile` → 可进入并修改密码。
  4. 未登录直接访问 `/profile` → 被 `RequireAuth` 踢到 `/login`。
  5. 普通用户 `localStorage` 里的 `USER_INFO_KEY` 若为旧版本（无 `menus`），刷新后需重新登录以拿到新版菜单。
