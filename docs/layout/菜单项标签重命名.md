# 菜单项标签重命名

## 1. 背景与目标

当前侧栏菜单中，「前台」分组下的子项命名风格与「后台」分组不一致：后台分组统一采用「xx管理」后缀（如「角色管理」「菜单管理」），而前台分组使用的是「AI 用户」「书籍列表」「AI 日志」等命名，缺少统一后缀，导致视觉与语义上的割裂。同时，为配合新增的知识库模块，需要在前台分组中新增「知识库管理」菜单项，并在后端种子数据中同步调整所有新增菜单项的 order 排序、扩展普通用户角色的可见菜单范围以及更新角色描述文案。

本专题的核心目标：

- 统一前后台分组下的子菜单命名风格，全部采用「xx管理」格式；
- 在前台分组新增「知识库管理」子项，并补全对应的后端种子菜单条目；
- 重新编排新增菜单项（知识库列表、AI 日志、后台日志）的 order 值，确保顺序稳定；
- 扩展普通用户角色的菜单可见范围，新增 `/ai-knowledge` 路径；
- 更新普通用户角色的描述文案，使其反映新的权限边界。

> 注意：本专题只覆盖上述改动点，知识库模块本身的实体、接口、页面实现请参见对应专题文档。

---

## 2. 改动范围

本次改动涉及以下两个文件：

| 文件 | 改动点 |
| --- | --- |
| `apps/frontend/src/router/menu.ts` | ① `lucide-react` 图标 import 新增 `Database`；② 前台分组 `menuItems.children` 中 3 项标签重命名（AI 用户 → 用户管理、书籍列表 → 书籍管理、AI 日志 → 日志管理）并新增「知识库管理」子项。 |
| `apps/backend/src/services/seed/seed.service.ts` | ① `DEFAULT_MENUS` 数组新增「知识库列表」条目（path=`/ai-knowledge`、order=7）；② 原有 AI 日志 order 由 7 改为 8，后台日志 order 由 8 改为 9；③ `USER_MENU_PATHS` 新增 `/ai-knowledge`；④ `ensureUserRole` 方法中角色描述文案由「书籍列表」更新为「书籍与知识库」。 |

---

## 3. 实现思路

### 3.1 命名风格统一

后台分组下的子菜单采用「管理员」「角色管理」「菜单管理」「后台日志」的命名，其中「管理」后缀已经体现出管理后台的语义。为了让前台分组保持一致，将原有的「AI 用户」更名为「用户管理」，「书籍列表」更名为「书籍管理」，「AI 日志」更名为「日志管理」，新增项命名为「知识库管理」。由此，前台分组下的所有子项也全部以「管理」结尾，整体命名风格统一。

### 3.2 order 顺序编排

后端种子数据 `DEFAULT_MENUS` 的 order 字段决定了菜单在列表中的升序排列顺序。本次新增的知识库列表需要插入到书籍列表（order=6）之后，因此将其 order 设为 7。原有的 AI 日志（order=7）顺延为 8，后台日志（order=8）顺延为 9。最终完整序列为：仪表盘(1) → 管理员(2) → 角色管理(3) → 菜单管理(4) → AI 用户(5) → 书籍列表(6) → 知识库列表(7) → AI 日志(8) → 后台日志(9)。

### 3.3 普通用户权限扩容

普通用户原仅可见 `/ai-ebooks`（书籍列表）菜单。为了让前台关联账号能够访问新增的知识库模块，在 `USER_MENU_PATHS` 常量中追加 `/ai-knowledge`，并在 `ensureUserRole` 方法中同步更新角色描述文案为「仅可查看关联前台账号的书籍与知识库」，无论是新建角色还是同步已有角色，描述都会一并刷新。

### 3.4 前后端菜单一致性

虽然前端侧栏展示的是 `menuItems` 静态数组，后端种子的是 `DEFAULT_MENUS` 数据库菜单表，但两者需要保持 path 与语义一致，否则前端路由（`/ai-knowledge`）无法通过后端角色菜单的 `collectAllowedPaths` 过滤。本次改动中前端新增的 `/ai-knowledge` 路径与后端种子新增条目保持一致，保证角色权限校验链路完整。

### 4.4 seed.service.ts：USER_MENU_PATHS 与 ensureUserRole 角色描述

**改动前** · `apps/backend/src/services/seed/seed.service.ts`（基线，`USER_MENU_PATHS` 常量 + 完整 `ensureUserRole` 方法）

```typescript
/** 普通用户默认可见菜单 path */
// 定义普通用户（非超管、角色 name=普通用户）默认能看到的菜单项路径数组，初始仅包含书籍列表
const USER_MENU_PATHS = ['/ai-ebooks'];
// ………… 中间省略 SeedService 类声明、ensureMenus、ensureAdminRole 等其余方法 …………
/** 普通用户：仅「书籍列表」菜单 */
// 私有异步方法：确保普通用户角色（id=2 或 name='普通用户'）存在且菜单关联准确
private async ensureUserRole() {
        // 根据 USER_MENU_PATHS 从菜单表中查出对应的菜单实体数组，后续用于关联角色
        const userMenus = await this.menusRepo
                // 使用 QueryBuilder 构建菜单查询，别名 m
                .createQueryBuilder('m')
                // 条件：path 字段落在 USER_MENU_PATHS 数组中（使用 IN 子句，:paths 为命名参数）
                .where('m.path IN (:...paths)', { paths: USER_MENU_PATHS })
                // 执行查询并返回多条记录
                .getMany();

        // 声明本地变量 userRole，用于存储查询到或新建的普通用户角色实体
        let userRole =
                // 优先按 id=2 查询角色，并同时加载 menus 关联关系
                (await this.rolesRepo.findOne({
                        where: { id: 2 },
                        relations: ['menus'],
                })) ||
                // 若 id=2 不存在，则按 name='普通用户' 兜底查询，并加载 menus 关联
                (await this.rolesRepo.findOne({
                        where: { name: '普通用户' },
                        relations: ['menus'],
                }));

        // 若两种查询方式都未命中，则说明角色不存在，需要新建并写入初始菜单
        if (!userRole) {
                // 使用 rolesRepo 的 create + save 两阶段方式持久化新角色
                userRole = await this.rolesRepo.save(
                        // 根据传入对象创建 Role 实体实例

        const have = new Set((userRole.menus || []).map((m) => m.id));

                // 更新角色描述（改动前：仅书籍列表），确保描述与实际权限一致
                userRole.description = '仅可查看关联前台账号的书籍列表';
                // 将修改后的角色实体保存回数据库
                await this.rolesRepo.save(userRole);
```

## 5. 兼容性与影响

| 维度 | 影响说明 | 处理策略 |
| --- | --- | --- |
| 前端标签硬编码引用 | 若其他地方（如面包屑、页面标题）引用了原标签「AI 用户」「书籍列表」「AI 日志」，可能存在展示不一致。 | 面包屑由 `resolveMenuLabel` 自动从 `menuItems` 取 label，无需额外改动；若有硬编码文案需另行搜索并同步。 |
| 后端菜单数据的 order 字段 | 旧环境中菜单表已写入旧 order（AI 日志=7、后台日志=8），新增知识库后 order 可能冲突或顺序不正确。 | `ensureMenus` 需具备按 path 幂等更新 order / acl / icon 的能力；若仅 insert 不 update，需手工执行 SQL 同步 order。 |
| 旧库中缺少 `/ai-knowledge` 菜单记录 | 升级时若 `ensureMenus` 不处理缺失项的新增，普通用户的 `ensureUserRole` 查询 `userMenus` 会取不到该菜单，导致角色关联不到。 | 确保 `ensureMenus` 在应用启动时按 `DEFAULT_MENUS` 补齐缺失的 path，并刷新已有的 name/icon/acl/order。 |
| 普通用户角色描述缓存 | 若前端界面某处提前缓存了「仅可查看关联前台账号的书籍列表」描述文本，不会自动更新。 | 角色描述读取均来自 roles 表，升级后 `ensureUserRole` 会在下次启动时刷写新描述，无需手工处理。 |
| `resolveHomePath` 默认回退路径 | 该方法末尾硬编码 `'/ai-ebooks'` 作为普通用户无任何权限时的兜底，本次未改动，仍回退到书籍列表。 | 若未来普通用户默认权限不包含书籍列表，需同步调整此回退路径。 |
