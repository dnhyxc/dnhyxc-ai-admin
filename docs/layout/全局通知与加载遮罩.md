# 全局通知与页面加载遮罩

## 1. 背景与目标

之前版本存在三个横切体验问题：

1. **403 权限不足的提示**：HTTP 封装层只处理 401（踢回登录），遇到 403 时直接走通用 `message.error` 顶栏红条。但权限不足往往是「用户不具备某个角色菜单的访问能力」或「普通用户点了超管按钮」，这种场景是**持续性**的（当前页所有操作都会失败），用短 Toast 一晃而过会让用户困惑。
2. **各页面独立的 loading/error state 重复**：AI 电子书、知识库、学习笔记、AI 日志等 6 个「AI 业务库敏感」页面都各自维护 `const [error, setError] = useState('')`、`const [loading, setLoading] = useState(true)`，每个页面都用相同的 Alert/骨架模式写一遍，且页面间样式略有差异。
3. **加载体验不统一**：列表加载中用户仍能点击按钮，容易触发重复请求或进入半加载态。

本专题引入「全局通知」与「页面级加载遮罩」两套统一机制：

- `NoticeStore`：MobX Store 统一管理三条状态——`visible`（显示全局 Alert）、`message`（Alert 文案）、`pageLoading`（全屏遮罩 Loading）。
- `AdminLayout`：在 `<Outlet />` 上方渲染 antd `Alert`（warning 型、可关闭），其下方绝对定位覆盖全屏 Loading 组件；路由切换时自动 `noticeStore.hide()`，避免上一页的错误提示带到下一页。
- `fetch.ts`：403 分支不再走 `message.error`，改为 `noticeStore.show(msg)`，让整页顶部保留一条稳定提示；`silent: true` 时不弹。
- 10 个列表/详情页（Dashboard / Menus / Logs / Users / Roles / AiUsers / AiEbooks / AiKnowledge / AiLearningNote / AiLogs）统一改造：
  - 进入请求前 `noticeStore.setPageLoading(true)`，`finally` 中 `false`，替代各页局部 `loading`。
  - AI 业务库错误由各页 `setError()` 改为 `noticeStore.show()`，替代重复的 Alert 区块。
  - `Table.emptyText` 改为「有全局提示时显示空格」避免「暂无数据」与 Alert 信息叠加误导。

延伸阅读：[Loading 组件](../ui/Loading%20组件.md)（遮罩内部使用的炫酷加载动画）。

## 3. 实现思路

- **全局 Store 单向流**：页面或 fetch 层调用 `noticeStore.show / hide / setPageLoading` 改变可观察字段，`AdminLayout` 通过 MobX observer 响应式渲染，无需在各页面声明额外 React 状态。
- **Loading 遮罩的视觉与交互**：`z-index: 50` + `absolute inset-0` + `bg-background/80`，覆盖 `<Outlet />` 内容但不覆盖 Alert；用户在加载中既看得见加载动画也看得见顶部提示。
- **403 与一般错误的分流**：403 是整页/持续性操作受限 → 用全局 Alert（保留时间长）；401 → 踢回登录；其余 → 仍走 `message.error`（短暂）。
- **多页改造的模式一致化**：
  - 列表页：解构 `{ authStore, noticeStore } = useStore()`，`load` 前后 `setPageLoading`，AI 业务库异常改为 `noticeStore.show(e.message || 'AI 业务库不可用...')`。
  - 各页原有 `error` state 与独立 Alert 块全部删除（与全局 Alert 冲突）。
  - `Table.locale.emptyText`：当 `noticeStore.visible` 时返回 `' '`，使表格空白区域不显示「暂无数据」灰色误导信息。
- **路由切换自动清除**：`AdminLayout` 里监听 `location.pathname`，切路由就 `noticeStore.hide()`，保证每个页面干净进入。

```typescript
// 引入 MobX 的 makeAutoObservable，自动把所有字段标记为 observable、方法标记为 action
import { makeAutoObservable } from 'mobx';

// 导出 NoticeStore 类（挂载到 RootStore.noticeStore）
export class NoticeStore {
        // 当前全局 Alert 展示的提示文案
        message: string = '';
        // 是否展示全局 Alert（顶部 warning 条）
        visible: boolean = false;
        // 是否展示「全屏 Loading 遮罩」，页面层请求发起/结束时成对 set
        pageLoading: boolean = false;

        // 构造函数：makeAutoObservable 自动推导可观察性
        constructor() {
                makeAutoObservable(this);
        }

        // action：显示全局 Alert，同时保存 message
        show(message: string) {
                this.message = message;
                this.visible = true;
        }

        // action：隐藏全局 Alert，并清空 message（避免下次显示旧值闪烁）
        hide() {
                this.visible = false;
                this.message = '';
        }

        // action：设置页面级加载遮罩的显示/隐藏
        setPageLoading(v: boolean) {
                this.pageLoading = v;
        }
}
```

### 4.3 `fetch.ts` 403 分支接入全局 Alert（`apps/frontend/src/utils/fetch.ts`）

**改动前** · `apps/frontend/src/utils/fetch.ts`（基线，约 L1–L100）

```typescript
// 引入 antd message 作错误 Toast
import { message } from 'antd';
// 全局常量：后端 base URL、token key、userInfo key
import { BASE_URL, TOKEN_KEY, USER_INFO_KEY } from '@/constants';

// 请求配置接口：与 http.get/post/put/delete 第二参数对齐
export interface RequestConfig {
        // 路径 params：会拼到 path 后面，以 / 分隔
        params?: Array<string | number>;
        // 查询字符串：会转成 URLSearchParams
        querys?: Record<string, any>;
        // 请求 body 数据
        data?: any;
        // 自定义请求头
        headers?: Record<string, string>;
        // 静默模式：不弹错误 Toast/Alert（静默接口调用）
        silent?: boolean;
}

// 统一后端响应体结构
export interface ResponseData<T = any> {
        // 业务码
        code: number;
        // 响应数据
        data: T;
        // 是否成功
        success: boolean;
        // 失败/成功消息
        message: string;
}

// antd message 全局配置：最多同时 1 条，2.5 秒自动消失
message.config({ maxCount: 1, duration: 2.5 });

// 简易 Toast 去重：最近 2 秒内相同文案不重复弹
const recentToasts = new Map<string, number>();
// 去重窗口 2000ms
const TOAST_DEDUP_MS = 2000;

// 错误 Toast：走 antd message.error，带去重
function toastError(msg: string) {
        const now = Date.now();
        // 查找上次相同 msg 的时间戳（不存在则 0）
        const last = recentToasts.get(msg) || 0;
        // 2 秒内相同消息直接丢弃
        if (now - last < TOAST_DEDUP_MS) return;
        // 记录本次时间
        recentToasts.set(msg, now);
        // 调用 antd 红条 Toast
        message.error(msg);
}

// 读取本地存储的 token（登录时写入）
function readToken() {
        return localStorage.getItem(TOKEN_KEY) || '';
}

// 拼接完整 URL：path + params + querys
function buildUrl(path: string, config?: RequestConfig) {
        // 先把 BASE_URL 末尾 / 去掉，path 开头 / 去掉；避免双斜杠或漏斜杠
        let url = `${BASE_URL.replace(/\/$/, '')}/${path.replace(/^\//, '')}`;
        // 若有路径 params，逐个 encodeURIComponent 后用 / 拼接
        if (config?.params?.length) {
                url += `/${config.params.map(encodeURIComponent).join('/')}`;
        }
        // 若有 querys：转成 URLSearchParams
        if (config?.querys) {
                const qs = new URLSearchParams();
                // 遍历键值对
                for (const [k, v] of Object.entries(config.querys)) {
                        // 空值不写入（undefined / null / 空串）
                        if (v !== undefined && v !== null && v !== '') qs.set(k, String(v));
                }
                const s = qs.toString();
                // 非空才加 ?
                if (s) url += `?${s}`;
        }
        return url;
}

// 核心请求函数：method + path + config，返回 ResponseData<T>
async function request<T>(
        method: string,
        path: string,
        config?: RequestConfig,
): Promise<ResponseData<T>> {
        // 默认请求头：JSON；并叠加用户自定义
        const headers: Record<string, string> = {
                'Content-Type': 'application/json',
                ...(config?.headers || {}),
        };
        // 读取 token 拼 Authorization
        const token = readToken();
        if (token) headers.Authorization = `Bearer ${token}`;

        // 调用浏览器原生 fetch
        const res = await fetch(buildUrl(path, config), {
                method,
                headers,
                // data 非 undefined 才序列化作为 body
                body: config?.data !== undefined ? JSON.stringify(config.data) : undefined,
        });

        // 尝试解析 JSON body；解析失败视为 null
        const json = (await res.json().catch(() => null)) as ResponseData<T> | null;

        // 401：未登录或 token 失效 —— 清登录态 + 跳登录
        // 仅未登录 / token 失效才清会话；403 无权操作不踢回登录
        if (res.status === 401) {
                // 删除本地 token
                localStorage.removeItem(TOKEN_KEY);
                // 删除本地 userInfo 缓存
                localStorage.removeItem(USER_INFO_KEY);
                // 非静默时弹提示
                if (!config?.silent) toastError(json?.message || '请先登录后再试');
                // 防止死循环：已在 /login 不跳
                if (!location.pathname.startsWith('/login')) {
                        location.href = '/login';
                }
                // 抛错让调用方 catch
                throw new Error(json?.message || 'Unauthorized');
        }

        // 其余失败：无 JSON / success:false / res.ok=false 都统一抛错
        if (!json || json.success === false || !res.ok) {
                // 优先 message，否则拼状态码
                const msg = json?.message || `请求失败 (${res.status})`;
                // 非静默走 Toast
                if (!config?.silent) toastError(msg);
                throw new Error(msg);
        }

        // 成功：返回 json
        return json;
}

// 导出 http：四个方法
export const http = {
        get: <T>(path: string, config?: RequestConfig) =>
                request<T>('GET', path, config),
        post: <T>(path: string, config?: RequestConfig) =>
                request<T>('POST', path, config),
        put: <T>(path: string, config?: RequestConfig) =>
                request<T>('PUT', path, config),
        delete: <T>(path: string, config?: RequestConfig) =>
                request<T>('DELETE', path, config),
};
```

## 5. 行为变化与兼容性

| 维度 | 行为 |
|------|------|
| 403 报错展示 | 由短暂 `message.error`（2.5s）改为 AdminLayout 顶部 `Alert.warning`（持续可关闭、路由切换自动清）。 |
| 页面加载遮罩 | 10 个页面请求期间展示居中 Loading 遮罩，用户无法误操作按钮。 |
| 独立 Alert vs 全局 Alert | AI 依赖页原有独立 Alert 块全部移除；全局统一位置与样式。 |
| `silent: true` 请求 | 与旧版一致：不弹 Toast 也不显示全局 Alert。 |
| 路由切换 | 自动 `noticeStore.hide()`；上一页的 403 提示不会污染下一页。 |
| Loading 组件降级 | 仅依赖 CSS var `--color-primary` 与 framer-motion；主题色切换自动联动（详见 Loading 组件专题）。 |

## 6. 测试与回归建议

1. 以普通用户账号登录 → 手动将浏览器地址拼到超管才能访问的页面（如 `/users`）→ 顶部应出现黄色 warning Alert，内容为「无权操作」；切换到其他有权限的页面（如 `/profile`）→ Alert 自动消失。
2. 关掉 dnhyxc-ai MySQL → 重新访问「电子书/知识库/学习笔记」任一 AI 页面 → 顶部显示全局 Alert 提示 AI 库不可用；表格显示为空白（不显示「暂无数据」以免误导）。
3. 打开浏览器 DevTools 把网速调到 Slow 3G → 进入「用户管理」或「仪表盘」→ 能看到居中 Loading 动画遮罩，期间点击表格行/按钮不会有任何反应（符合预期）。
4. 用超管在「角色管理」新建一个完全没配菜单的角色 → 用该角色用户登录 → 点击侧栏仅有菜单 → 403 时应显示全局 Alert，且多次点击不会重复叠 Toast（走 NoticeStore，仅一份 message）。
5. `silent: true` 接口静默请求失败 → 不显示 Alert（验证 fetch 层分支）。
