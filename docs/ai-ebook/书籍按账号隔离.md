# 书籍按账号隔离

## 1. 背景与目标

后台的「书籍列表」直接读取 `dnhyxc-ai` 业务库的 `ebook_book` 表。原实现对所有用户返回全量书籍，普通用户登录后能看到所有前台用户的书籍，存在数据越权风险。本专题实现：

- 基于当前登录后台用户的 `aiUserId`（绑定的前台账号 id）隔离书籍查询。
- 超管保持全量视图；普通用户仅返回其绑定前台账号的书籍。
- 未绑定前台账号的普通用户查询时直接返回空列表，避免误查。
- 前端同步：普通用户侧隐藏「按用户名搜索」输入框，只保留书名过滤，并在文案上明确展示当前查询范围。

## 2. 改动范围

- `apps/backend/src/services/ai-ebook/ai-ebook.controller.ts`
- `apps/backend/src/services/ai-ebook/ai-ebook.service.ts`
- `apps/frontend/src/views/ai-ebooks/AiEbooksPage.tsx`

## 3. 实现思路

1. 控制器在收到请求时通过 `@Req()` 读取 JWT 里的 `userId`，查出后台用户的 `roles` 与 `aiUserId`，判断是否超管。
2. 把「查询范围」编码成 `scopeAiUserId` 参数传入 `AiEbookService.findAll`：
   - 超管 → `scopeAiUserId = undefined`（不过滤）
   - 普通用户已绑定 → `scopeAiUserId = aiUserId`（只查该前台账号）
   - 普通用户未绑定 → `scopeAiUserId = null`（直接返回空）
3. Service 层对 `scopeAiUserId === null` 快速短路返回空，再用 `qb.andWhere('book.userId = :aiUserId', { aiUserId })` 做行级过滤。
4. 前端根据 `authStore.isSuperAdmin` 决定是否展示「用户名搜索框」以及底部文案。

### 4.1 `AiEbookController.getBooks` 范围识别

**改动前** · `apps/backend/src/services/ai-ebook/ai-ebook.controller.ts`（基线，约 L40-L55）

**改动后** · `apps/backend/src/services/ai-ebook/ai-ebook.controller.ts`（当前，`getBooks` 方法，约 L44-L75）

```typescript
// 新增 UserService 注入，用于反查后台用户及其角色
constructor(
	private readonly aiEbookService: AiEbookService,
	private readonly userService: UserService,
) {}

@Get('/getBooks')
async getBooks(
	// 从 JWT 中取得 userId
	@Req() req: Request & { user?: { userId?: number } },
	// 查询参数：pageNo / pageSize / title / username
	@Query() query: GetAiEbooksQuery,
) {
	// 用 JWT userId 反查后台用户（包括 roles 与 aiUserId）
	const adminUser = req.user?.userId
		? await this.userService.findOne(req.user.userId)
		: null;
	// 判定是否超管：角色列表里存在 ADMIN id 或名为「超级管理员」
	const isAdmin = Boolean(
		adminUser?.roles?.some(
			(r) => r.id === Role.ADMIN || r.name === '超级管理员',
		),
	);

	// 把「范围」编码到查询对象里，service 按需过滤
	return this.aiEbookService.findAll({
		...query,
		// 超管不过滤；普通用户按 aiUserId 过滤；未绑定则传 null 表示空结果
		scopeAiUserId: isAdmin ? undefined : (adminUser?.aiUserId ?? null),
		// 普通用户禁用按他人 username 搜全库
		username: isAdmin ? query.username : undefined,
	});
}
```

**变更摘要**：控制器层做身份识别与查询参数裁剪，将隔离范围通过 `scopeAiUserId` 显式传给 Service。

### 4.2 `AiEbookService.findAll` 按 `scopeAiUserId` 隔离

**改动前** · `apps/backend/src/services/ai-ebook/ai-ebook.service.ts`（基线，`findAll` 片段，约 L20-L50）

**改动后** · `apps/backend/src/services/ai-ebook/ai-ebook.service.ts`（当前，`findAll` 方法，约 L24-L65）

```typescript
async findAll(query: {
	pageNo?: number;
	pageSize?: number;
	title?: string;
	username?: string;
	// 新增：普通用户隔离字段
	scopeAiUserId?: number | null;
}) {
	this.assertReady();

	// 普通用户未关联前台账号：直接返回空，避免误查全库
	if (query.scopeAiUserId === null) {
		return { list: [], total: 0 };
	}

	const pageNo = query.pageNo || 1;
	const pageSize = query.pageSize || 20;

	const qb = this.aiEbookRepository.createQueryBuilder('book');

	// 新增：普通用户只看其绑定的前台账号的书籍
	if (query.scopeAiUserId != null) {
		qb.andWhere('book.userId = :aiUserId', {
			aiUserId: query.scopeAiUserId,
		});
	}

	// 原有的用户名过滤
	if (query.username) {
		qb.leftJoinAndSelect('book.user', 'u')
			.andWhere('u.username LIKE :username', { username: `%${query.username}%` });
	}

	// 原有的标题过滤、分页、排序保持不变
	// ...
}
```

**变更摘要**：Service 层对 `scopeAiUserId` 做显式分支处理：`null` 直接空结果，具体 id 则拼 `andWhere` 做行级过滤。

## 5. 兼容性与影响

- 对超管无任何行为变化，仍可按全量视图。
- 普通用户在完成绑定前查询书籍会得到空列表；绑定完成后立即生效，无需重新登录。
- 普通用户在「书籍列表」页按书名过滤仍可用；按用户名过滤被禁用。

## 6. 风险与回归

- 回归建议：
  1. 超管 → 书籍列表 → 全量可见，用户名搜索框可见。
  2. 未绑定普通用户 → 书籍列表 → 空列表 + 「尚未绑定前台账号」文案。
  3. 已绑定普通用户 A → 仅看到自己绑定账号的书籍，看不到 B 的书。
  4. 已绑定普通用户 A 直接构造带 `username` 的查询 → 后端自动忽略该参数，仍按 `scopeAiUserId` 过滤。
  5. 绑定到不存在书籍的前台账号 → 空列表，不应抛错。
